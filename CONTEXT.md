# Archimedes Desktop

A cross-platform (Windows/macOS/Linux) desktop app, built with Tauri 2, that runs coding agents in-process — the desktop's own Rust runtime is the only **Agent harness** (a **Native session** — ADR 0022).

## Language

**Client**:
The Archimedes Desktop application itself — the **Client** role: it is the **Supervisor** (worker lifecycle + sole SQLite writer + the response side of the permission/interactive gates — ADR 0025), renders the conversation, and provides the settings/skills/MCP surfaces.
_Avoid_: App, frontend, IDE, desktop (too generic)

**Agent**:
The conversation *partner* — the thing that produces the assistant's responses. Always embodied in the desktop's own **Agent harness** (a **Native session** — ADR 0022), which runs in a **Worker process** (ADR 0025) — never an external agent process. _Generalized 2026-10-06: a native session has no subprocess; the partner is embodied in the desktop's own runtime. 2026-10-02: the external (pi) embodiment is removed — the harness is the desktop's own runtime, full stop. 2026-10-04: the harness runs in a Worker process (ADR 0025) — still the desktop's own binary, never an external agent._
_Avoid_: Subagent, worker, bot, assistant. (Note: in the pi-archimedes project "Agent" means a subagent configuration — different meaning, different project. "Subagent session" is the desktop's term for a desktop-spawned delegated session — see its entry below.)

**Agent harness**:
The machinery that runs an agent conversation end-to-end — the model loop (model call → tool dispatch → retry/compaction) + the tool registry + session persistence + provider integration. A harness is a *runtime*, not a model: the desktop's own Rust runtime is the **only** harness (ADR 0022 — the external pi harness embodiment is removed), running in a **Worker process** (ADR 0025). The harness owns the conversation's *control flow*; the model only produces tokens, the tools only act on the world.
_Avoid_: Agent (that's the conversation *partner*; a harness *runs* it), loop, brain, runtime (too generic)

**Space**:
A single on-disk folder the Client can open — the workspace in which a conversation and its file access happen. Identified by the folder's canonical path, not a user-supplied name; the display label is the folder's base name. Multiple live Sessions may coexist per Space as well as app-wide; stored conversations of a Space survive. Closing its tab FORGETS the Space and deletes nothing — no `sessions` row is touched, so re-opening the folder returns the Space with its history; a Space still holding a live **Session** confirms first, because the rows live under the Space and a closed tab has removed the very surface the Client's stop control lives on — **Stop** is the sidebar row's button — so the Session keeps running with no surface left to reach it (the Esc path reaches only the Session on screen) — ADR 0043, amended 2026-10-20.
_Avoid_: Project, workspace, folder, directory, environment

**Session**:
One live conversation, backed by the desktop's **Agent harness** running in a **Worker process** (a **Native session** — ADR 0022/0025; the external embodiment is removed). The unit of lifecycle, history, and permission state. A Session lives inside one **Space**: its `cwd` is the Space's folder and the seed of the Space's **Boundary** (the **Beyond-boundary policy** decides what happens beyond it — ADR 0030); a Space's active conversation is its most recent Session. _Generalized 2026-10-06: a native session has no external subprocess; embodiment is a harness, not an agent process. 2026-10-04: the harness runs in a Worker process (ADR 0025) — the session's embodiment is a Worker, and the Client is its Supervisor._
_Avoid_: Conversation, chat, thread, run

**Native session**:
A **Session** — the desktop's own Rust runtime is the **only** **Agent harness** (ADR 0022): no external agent process. Runs in a **Worker process** (ADR 0025) driven by the desktop's own AgentLoop, which calls the model directly (an OpenAI-compatible provider) and executes tools in the Worker (Rust executors); the **Supervisor** persists the transcript to SQLite from the event stream (the Worker has no DB).
_Avoid_: In-process session, local session, built-in session

**Session incarnation**:
One **Worker**'s life within a **Session**'s transcript. A **Session** keeps its id across a **Resume**, but every `messageId` the harness mints is stamped with the incarnation that minted it (`a3f9c1:m1`, `a3f9c1:system`) — so two Workers of one Session can never write the same harness-minted display row, constants included, and a **Retraction** can only ever name rows its own Worker wrote (ADR 0049) — with one residue among the keys it stamps: the no-`messageId` fallback key `default` stays BARE on both sides, so it is the only stamped-shape key still able to be shared by two lives (§6 of `compaction-recovery-hardening-follow-ups.md`, recorded as a residue rather than a defect). The `tool-call` rows are the family ADR 0049 never scoped at all — keyed by the provider's own `toolCallId`, so no stamp of ours reaches them (§7, same document). The stamp arrives on the start envelope, minted per `Start` by the **Supervisor**: the Worker is told its own boundary rather than inventing it.
_Avoid_: generation, epoch, version, nonce, salt (the stamp is not a security value), new session (a Resume keeps the Session's id — that is the whole problem)

**Anchor** (the context snapshot's):
The last `Usage` the **Agent harness**'s **Provider** reported for a **Session** — `input + output`, which already IS the whole context the model was shown plus that reply's own output — held in the `Compactor`. `input_tokens` is the WHOLE prompt, **cached prefix included**: each **Provider**'s parser makes that true (ADR 0046), which is why the `Compactor` never needs wire knowledge. A Session's context size is the anchor PLUS the local estimate of the messages appended after it (the *trailing* term), and that ONE number feeds both the compaction threshold and the composer's context bar (ADR 0028). To **re-anchor** is to recompute the snapshot after the transcript grows (`note_context`); the only paths that move the anchor DOWN are the resets — `reestimate` (resume / post-compaction), which CLEARS it, and `turn_abandoned`, which retracts a reply a cancelled or failed turn never persisted.
_Avoid_: Accumulated usage (the pre-ADR-0028 metric this replaced — never what the anchor is), prompt size (`input_tokens` alone, which omits the reply), current count (the SNAPSHOT — anchor + trailing — not the anchor). "Baseline" is reserved for what `reestimate` leaves behind, i.e. the estimate that REPLACES and clears the anchor. Unrelated to UI/window anchoring.

**compaction reason**:
Which of the three entry points started a **compaction** — `manual` (a **Composer command**), `threshold` (the **Anchor** + trailing snapshot crossed `context_window − reserve_tokens` at the top of the turn's loop), or `overflow` (the **Provider** refused an oversized request, which is compacted and retried IN the same turn — ADR 0045). It rides `compaction_start` / `compaction_end` and the `compaction_update` frame; the **working indicator** shows ONE label ("Compacting") whatever the reason. _Avoid_: `context_limit` (the hardcoded value both emit sites used), trigger, cause, "auto vs manual" (the two-tier label scheme the UI rejected)

**compaction card**:
The **transcript** row a **compaction** leaves behind — a **tool call** card like any other, announced by `compaction_start` and settled by `compaction_end`, whose expanded body is the SUMMARY the summariser produced (the thing the model was replayed and the user could not previously read). Its title is the display-only name `compaction`, which is NOT a dispatched tool: it is absent from the tool specs, so the model can never call it. One card per **compaction**, keyed `{incarnation}:compact:N` — a shared key would merge a session's compactions into one row, the defect the **one-liners** this replaced had (ADR 0077). _Avoid_: compaction message, system line (what it replaced), notice

**Watermark** (the context snapshot's):
How many transcript messages the anchor's `Usage` report already covers — the boundary that keeps the anchor and the trailing estimate DISJOINT so the snapshot cannot double-count (the estimate covers only the messages at or past it). `record_usage` writes it optimistically as `len + 1` ("the reply lands at index `len`"), and `turn_abandoned` pulls it back at any turn exit that persisted no reply, so the NEXT turn's prompt is not swallowed by the window and left unmeasured (ADR 0028). A Session that never sees a usage report has anchor `0` and watermark `0` — the whole transcript is trailing (ADR 0028).
_Avoid_: Cursor, checkpoint, high-water mark (used of unrelated offsets)

**Summary input budget**:
How much of the older set one **compaction** may hand the summariser in ONE request: `context_window − output cap − min(reserve_tokens, 4096)`, where the output cap (`⌊0.8 × reserve_tokens⌋`, clamped to 8 192) is also the summary's `max_tokens`. The overflow beyond it is the **trim** — the OLDEST messages, never summarized — and it is recorded, not silent: a harness-written count lands in the summary row and the model is told at generation time (ADR 0047). _Avoid_: truncation (what the provider does to a reply), context window (the model's bound; this is the summariser's slice of it), "summarize what fits" (which of the two sides gets trimmed is the whole decision).

**Session cost**:
A **Session**'s running USD total — the SUM of the per-call figures the **Provider** itself reports on each response (the per-call figure the Provider's own usage object reports — read from the response BODY as the FIRST PRESENT of `usage.cost` → `usage.cost_details.upstream_inference_cost` → `usage.estimated_cost`; the `x-litellm-response-cost` header is the rejected design, because it commits before a stream ends and this app always streams), never a derivation from tokens against a price table. Carried as `Option<f64>` on `ProviderEvent::Usage` and pushed on the `cost_update` channel the renderer has long held a slot for; a **Subagent session**'s cost rolls up into its parent's figure through `SubagentMetrics`. `None` means no call this session reported a cost — the honest answer for any Provider that prices nothing, and it renders as NOTHING; `Some(0.0)` is a real zero and renders as `$0.00`. The two are never collapsed into one number, which is why the field is an `Option` and not a float — and the same distinction is held at rest: the `sessions.cost_usd` column is nullable with no `DEFAULT`, so "never reported" and "reported zero" are different rows. The **Supervisor** accumulates it from the frames it already routes (the **Worker** holds no `Db`), so the figure survives a reload; a resumed **Session** is seeded from the row, DIRECTLY — never through the store's per-frame reducer, which sums and would add a stored total to itself. Unrelated to `Model.cost_per_mtok_*`, which the figure does not read.
_Avoid_: spend (the proxy's own word for its aggregate, not a session's), token cost (this is NOT computed from tokens — the whole design decision), estimated cost, price (a property of a model; this is a property of a session), `0.0` (never means "unknown")

**Cost channel**:
The `cost_update` **interactive event** — one `sessionId`-keyed frame per priced call, carrying that call's USD delta and a `source` (`main` for a turn of this Session, `subagent` for a **Subagent session**'s roll-up into its parent). ONE function emits it (`emit_cost_update`), and the rule it enforces is the whole contract: a `None` cost emits NOTHING AT ALL, while a `Some(0.0)` emits a frame — so absence travels as the ABSENCE OF A FRAME, never as `null` on the wire, and Rust never puts `null` on this bus. The store still spells its payload `number | null`, because by the time a frame reaches the renderer the honest statement "no frame this Session carried a figure" has to be representable; `combineSessionCost` keeps that honest (`null + null = null`, `null + x = x`) where the arithmetic it replaced manufactured a `$0.00` for a session that had never been priced. Deliberately NOT named by its call-site count: a count here goes stale the moment a second emitter lands, and the stale claim is the defect issue #110 exists to catch. _Avoid_: cost bus, cost stream, billing (the operator's concern, not this frame), price update (a price is a property of a **Model**; this is a figure for a **Session**)

**Collapse**:
To name **Session cost**'s two different states — "no call reported a figure" and "a call reported a real zero" — as ONE number. The defect ADR 0082 calls D5, and the reason every cost field in this app is an `Option` rather than a float. Both spellings of it: the type (`f64` where `Option<f64>` is honest) and the GATE (`> 0.0` / `!= 0` / `cost > 0` where the test wanted "is there a figure", because such a filter eats the real zero along with the absence — which is why `SessionCostLine` reads `null → nothing, 0 → $0.00` directly instead of routing through `formatCost`, whose answer for zero is the empty string). A **Collapse** is not under-counting: double-counting a figure a provider sent twice is the opposite error and a different defect. _Avoid_: zero-cost (says nothing about which state), missing data (the absence is OBSERVED, not unknown), null-vs-undefined (a representational detail; the domain distinction is reported-never vs reported-zero)

**Abandoned attempt**:
A **Provider** call whose partial output was already streamed and then discarded because the turn loop is retrying. TWO paths produce one today — the retryable-error retry and **overflow** recovery (ADR 0045) — and both must **retract** it. The model's own history never contained it; only the display did. _Avoid_: failed turn (the turn may well succeed on the retry), stale reply, partial response (the streamed bytes are only half the story — the thought segment is abandoned too).

**Retraction**:
The frame that erases an **abandoned attempt**'s already-streamed text and thought for its `messageId` so the live view, the persisted display row, and the model's history agree; the retry then streams into that same cleared id, so ONE `message_start` per assistant message still holds (ADR 0048). Silent when nothing had streamed. Its `messageId` is **incarnation**-scoped, so a Retraction can never reach a row some earlier Worker wrote (ADR 0049). NOT a **cancellation** (which stops work from happening) and NOT **compaction** (which rewrites the Provider's history, not the display). _Avoid_: rollback, retract the anchor (`turn_abandoned` moves the **Watermark**, which is a different thing entirely), undo.

**Worker process**:
One child OS process (the desktop's own binary, self-exec `archimedes --worker` — ADR 0025) that runs ONE session's **Agent harness** — the `AgentLoop` + tool executors + provider client — speaking a stdio JSONL protocol to its **Supervisor**. Worker lifetime = session lifetime (a main session's Worker is reaped at session end / app quit; a subagent's after `agent_settled`) — so a **Session** is a SEQUENCE of **incarnations**, one per Worker (ADR 0049). The Worker has no DB (its `SessionStore` is a no-op; the conversation is in-memory) and takes its resolved **Provider** config from the protocol envelope rather than reading it, though it does read `settings.json` in-process for the things the Client cannot hand it per-session — the `mcpServers` layer, the **Agent override** map, and the **Beyond-boundary policy** (ADR 0025 + ADR 0030). A Worker crash degrades to a **Stalled session** or a `SubagentOutcome::Failed` tool error — never an app death.
_Avoid_: Child process, agent process, harness process

**Supervisor**:
The Tauri app process (the **Client**) in the Worker-process architecture (ADR 0025): React UI + WorkerManager (spawn / reap / crash-detect / abort-all) + sole SQLite writer (persists transcripts from the Worker event stream) + provider catalog + the response side of the permission/interactive gates (relays the user's answers back over the protocol).
_Avoid_: Main process, parent, daemon

**Tool child**:
An OS process spawned on the **Agent**'s behalf by a tool executor — `sh`/`cmd` from the shell tool, `fd`, `rg`. It has no channel back to us, so it gets `childproc`'s full child policy including a CLOSED stdin (`Stdio::null()`): nothing can ever feed it, and an inherited stdin handle means a command like `cat` waits forever on a pipe no one will write (ADR 0060, `docs/research/windows-child-console-window.md`).
_Avoid_: Agent child (reads as "a **Subagent session**", which is a **Worker** — the opposite category), subprocess, shell child

**Runtime child**:
An OS process the **Client** or **Worker** spawns to run *itself* rather than the Agent's command — the `--worker` self-exec, an MCP stdio server, the `sudo_exec` helper, the updater relaunch. Its stdin is a pipe WE write to (JSONL, JSON-RPC, a password), so `closed_stdin` must never touch it; only the window policy applies.
_Avoid_: Client child, long-lived child (an MCP server that exits is not long-lived), background process

**Pipe-held completion**:
The `bash` outcome where the command's foreground work FINISHED and its exit status was OBSERVED, but a backgrounded grandchild still held the output pipe open so the deadline fired anyway. It is a SUCCESS, reported as one, with a note that says the command completed, names its exit code, tells the model NOT to re-run it, and adds that a background process holding the pipe was killed. It is NOT a timeout — calling it one is what sent models retrying non-idempotent commands and inventing causes for the "failure". The note never claims the output was captured in full: the drain after the kill is bounded, and a grandchild that escaped the process group can outlive it.
_Avoid_: timeout (the report this exists to stop making), hung command, truncated run, "completed with warnings" (nothing warned — the command succeeded)

**Stalled session**:
A **Session** whose **Worker process** died (a crash, or a spawn failure) — the transcript is intact (persisted as events arrived), the last turn is incomplete (no `agent_settled` = incomplete), and the session offers a **Resume** action (a fresh Worker + the Supervisor-rehydrated transcript). A view/lifecycle state, distinct from **Archived** (a user action) and from a running session.
_Avoid_: Dead session, crashed session, orphaned session

**Crash log**:
The file a panic hook writes — `<data_dir>/archimedes/crash-<ts>-<tag>-<pid>.log` (`crashlog.rs`; ADR 0025 amended) — holding the panic message, its `file:line:column` and a forced backtrace, pruned after each successful write to the newest 30 days / 50 files (`MAX_CRASH_LOG_AGE_DAYS` / `MAX_CRASH_LOG_FILES`). The `<data_dir>` is HANDED to the hook at install time (`install_panic_hook(tag, dir)`): the hook resolves nothing at panic time, which is what keeps a test panic out of the real directory. It is a FILE in a directory, NOT evidence that a **Worker process** died: the panic hook is one process-global slot per process, so a panic on ANY thread of any process that installed a hook writes one — including a unit test's deliberate `panic!` landing in the hook a different test installed (into that hook's injected dir, never the user's). The only signal that a **Worker** actually crashed is the **Supervisor**'s unexpected-`Exited` → **Stalled session**; the pid in the name is what ties a log to the process that wrote it (the **Supervisor** selects by it when it fills `StalledInfo.crashLog`, and answers `null` rather than another Worker's log when that pid names no file). Read by no code — the **Stalled** banner only hands the path to **External open**.
_Avoid_: Crash (the log is not one), crash dump (nothing is dumped — no core file), stack trace (a section inside it), error log (**Supervisor**'s `ARCHIMEDES_DEBUG` `supervisor.log` is that one), panic log

**Archived session**:
A stored **Session** hidden from its **Space** group by an explicit user action (the `archived` flag on the `sessions` row) — listed in the sidebar's **Archived** section instead of its Space group. Archiving a stored Session is a view property — the flag and nothing else; archiving a LIVE one is a *lifecycle* action as well, because `archiveSession` closes the Session once the flag is committed and its **Worker process** is reaped with it (ADR 0016, amended 2026-10-20). The order is the whole design: flag, then the store move, then the close — so when `session-closed` lands, `handleSessionClosed`'s sticky rule (a closing archived Session is never filed under the stored list) is the thing that leaves the row in the **Archived** section alone, where close-first would race that async event and flicker the row through its **Space** group on the way out. Either way the transcript stays in the desktop's storage, the session is still openable and resumable (first send resumes it, as for any stored session), and the flag is **sticky** — it survives both the close that archiving a live Session causes and any **Resume** that follows, and changes only via explicit archive/unarchive. `stopSession` — the live row's OTHER hover action — never produces this state: it cancels a turn in flight (keeping the **Worker**) or closes an idle Session (dropping the row to stored, or — for the sticky live+archived pair, already in **Archived** — landing it back there), and touches no flag, so Stop is never what files a row under **Archived**. Delete is offered from the **Archived** section and from **Detached session**'s Settings surface — those are the two doors, both behind a confirm (ADR 0016, amended 2026-10-21). The Archived section is itself **Space-scoped**: it lists only the ACTIVE **Space**'s archived rows and counts only them, so an archived Session of a Space with no open tab is not listed there at all — it is **Detached** (ADR 0016, amended 2026-10-21). The section is the ONE list in the sidebar that is NOT under a **Manual order** — it is the sole surface that still sorts by recency, and since ADR 0075 it must do so EXPLICITLY (by `lastActiveAt`): the order it used to inherit free from `list_sessions` is the very order that change reassigned to `sort_order`, so a filter left reading input order would present a manual arrangement under a recency heading and pass every pre-existing test (ADR 0075).
_Avoid_: Paused session, closed session, hidden session

**Detached session**:
A stored **Session** whose `cwd` matches no **Space** row — a Session with no open tab, so the sidebar, which files every row under a Space, cannot show it at all. A view property of the sidebar and NOT of the Session: it changes when a tab is opened or closed, sets no flag, and touches no row — re-opening the folder makes it an ordinary row again. Listed in Settings → Detached sessions, which offers **Reopen Space** (`addSpace`, so the row returns to the sidebar) and Delete; its one bulk action, Clear all, is the widest blast radius in the app and is deliberately confined to a surface reached only on purpose (ADR 0016, amended 2026-10-21). Archived and unarchived rows both qualify — an unarchived Session of a closed Space has always been equally invisible.
_Avoid_: Orphaned session (already reserved under **Stalled session**; "an orphaned override" is the unrelated ADR 0023 term), abandoned session (an Archived row was put away deliberately — nothing left it), lost session, hidden session, Stalled session (a Worker that DIED, with a Resume affordance — nothing is wrong with a Detached one)

**Manual order**:
A list's user-owned sequence — the `sort_order` column on the `spaces` and `sessions` rows, seeded on upgrade from whatever order the list already had so nobody's arrangement changes on install. The ONLY thing that changes it is a drag: a new message, a Session closing, and a restart all leave a row exactly where it is, and a new **Space** or **Session** joins at the BOTTOM (`MAX + 1`). It governs the **Space** tab strip and one **Space**'s sidebar rows as ONE sequence spanning live and stored — live/stored stays visible as the row's status mark, never as a position rule — and it means ONLY position: it is never evidence of recency, and both read queries order by it so the store's "input order IS the order, do NOT re-sort" rule stays true rather than inverted (ADR 0075). The **Archived** section is the one list NOT under it.
_Avoid_: Custom order, pinned (nothing is pinned to a top — a pinned list still reshuffles below the pin), user sort (nothing sorts), manual pin, drag order (the drag is how it changes, not what it is)

**Landing Session**:
The **Session** the Client opens when the app boots, when a **Space** tab is clicked, or when the selected tab closes. Computed from recency and NEVER from list position — `recencyOf` (a loaded transcript's last stamp, else the row's `lastActiveAt`) picks the stored arm, with a LIVE Session still preferred over any stored one so a tab click shows a turn in flight. It is the reason a **Manual order** was affordable: four sites used to read "head of the list" as "most recent", and moving that question to an explicit field is what let position stop carrying meaning (ADR 0075).
_Avoid_: Default session, current session (that is the **Active session** — what is on screen, which a Landing Session merely sets at those three moments), most recent session (recency decides it, but the term names the DECISION, not the ranking), last session

**Session title**:
The short model-written name of a **Session**, generated by the **Supervisor** once its first exchange settles (ADR 0037) and stored on the `sessions` row. 3–8 words, capped at 80 chars, written from the first user message plus the first assistant answer after it. `NULL` until named, and named at most once: the write is `UPDATE … WHERE title IS NULL`, so a Session keeps the name it already has and nothing overwrites it — auto-only, with no rename affordance yet, which makes `Some(title)` mean exactly "the naming pass wrote this". The shared rule is `titleFor` (`src/lib/sessionTitle.ts`) — the title, else the first user message truncated to ~80 chars, else the **Space**'s folder name — used by the sidebar's session rows and by the close-tab confirm so the two can never name the same **Session** differently; the side-pane header still carries its own inline copy of that chain. A **Subagent session** is never titled.
_Avoid_: Session name, summary, slug, label

**Subagent session**:
A **Session** the desktop spawns to run a task delegated by the main agent — a **Worker process** running a native **AgentLoop** child (the parent's model/tools minus `subagent` and `list_agents`, plus optional `launch` overrides; its `agentName` resolves against discovered **Agent definitions** — ADR 0020; an unknown/omitted name is a config-less label-only dispatch). Unlike a **Session**, it is not a user-facing conversation — it exists to complete the delegated task, and its progress renders in the Client through the same event pipeline as a Session (its transcript is persisted as a hidden ephemeral row — ADR 0025). The subagent's interactive tools (ask, sudo_exec) run on the Worker's **interactive** channel, so their prompts go directly to the Client (the Supervisor's relay) without relaying through the main agent. They are answered in the PARENT's face, not the child's: a child's `ask` and **Permission prompt** render at the bottom of the parent's transcript when the parent is the active **Session**, and otherwise in the always-mounted `SubagentModals` host at the `App` root (`src/components/SubagentModals.tsx`); the child's `confirm`/`password` are Radix `Dialog`s and so always render in that host. The two sites are mutually exclusive — partitioned on "is this gate's parent the active **Session**", so a gate is never answerable twice and, while the workspace view is mounted, never rendered nowhere (the one accepted exception: the Settings view with the gate's parent the active Session — `App.test.tsx`'s known-hole pin) — and both read the one derivation `useChildGates`/`childGatesOf`. Opening the child's sheet shows its transcript, not its prompts. An **Attention alert** for a child's pause names the parent and ranks at the parent's position (ADR 0040, amended 2026-10-13). _Generalized 2026-10-01: a native-native subagent has no pi process and no bridge. 2026-10-02: the bridge-mode embodiment is removed (ADR 0022). 2026-10-04: a subagent session is a Worker process (ADR 0025) — ephemeral, no resume; a crash degrades to a `SubagentOutcome::Failed` tool error. 2026-10-13: a child's gates stopped hiding in the child's sheet and are answered in its parent's transcript (ADR 0040 amendment)._
_Avoid_: Worker, delegated task, child session, background session

**Active Subagent**:
A **Subagent session** that is either producing frames or is legitimately silent — blocked inside a tool execution, awaiting a nested **Subagent session**, or parked on a **gate** awaiting the user. An Active Subagent has NO timeout of any kind: there is no ceiling on how long a delegation may run (ADR 0055). Operationally: it holds at least one outstanding `tool_call_id`, or its **Worker process** has emitted a frame recently.
_Avoid_: Live subagent, running subagent, busy child

**Dead Subagent**:
A **Subagent session** that is neither producing frames nor legitimately blocked — silent, with no tool execution in flight, no nested delegation outstanding and no **gate** open — for the **Dead bound**. Only a Dead Subagent is ever reaped by the clock, and it settles `Failed { "unresponsive" }` (ADR 0055). Silence alone is not enough: a child parked on an unanswered `ask` is silent by construction and is **Active**, not Dead.
_Avoid_: Timed-out subagent, stuck child, hung worker (all three conflate "slow" with "wedged", which is exactly the distinction ADR 0055 exists to make)

**Gate**:
A **Session**'s paused-on-the-user wait for an answer to one interactive request — an `ask` question, a `confirm`/`password` prompt, or a **Permission prompt**. Identified by the interactive `requestId` (on the native path that IS the `toolCallId`, suffixed `:confirm` / `:password`), so a gate id is NOT globally unique. Leaving the set of open gate ids is the ONLY thing that ends a **waiting** attention pause — a Session's own silence never closes its gate (ADR 0040). A gate is held inside a tool execution, so a Session parked on one emits no frames while waiting.
_Avoid_: Modal, prompt (bare — that is the `Permission prompt` specifically), blocking tool, pending dialog

**Dead bound**:
The idle-based bound that reaps a **Dead Subagent** (`DEFAULT_SUBAGENT_DEAD_BOUND`, Supervisor-side, one per dispatch, 30 minutes). It measures a duration of UNEXPLAINED SILENCE **as the Supervisor OBSERVES it** — the gap between frames the pump actually read, not the frames the child sent, so a starved parent can observe silence in a child that never stopped producing — never a duration of the delegation, and it is rearmed on every observed frame and disabled while any `tool_call_id` is outstanding. Distinct from the provider's `read_timeout` (an idle bound on the time BETWEEN BYTES of one model response) and from a tool's own `timeout_ms` (per command) — three unrelated bounds that all used to be called "timeout".
_Avoid_: Settle timeout (the old name — `DEFAULT_SUBAGENT_SETTLE_TIMEOUT` read as an idle timer but was an absolute wall-clock cap on the whole delegation), subagent timeout

**Agent definition**:
A user-authored markdown file (flat, in a standard agents dir) with YAML frontmatter (`name`, `description`, `model`, `thinking`, `tools`) + a system-prompt body — discovered by the desktop like a **Skill** (space-level `.agents/agents` + `.pi/agents` walked to the repo root; user-level `~/.agents/agents` + `~/.pi/agent/agents`). Selectable in a **Subagent session** via the `subagent` tool's `agentName` (layered under explicit params — ADR 0020); advertised by the `list_agents` tool. The user-level agents dirs are readable through the **Boundary** but on the write deny-list (`boundary::protected_dirs`) — a session may not rewrite its own agent definitions (ADR 0030). Distinct from **Agent** (the conversation partner) — an Agent definition is a user-authored prompt + config, not a runtime.
_Avoid_: Agent config, agent preset, subagent preset

**Agents**:
The sidebar modal (the Space rail's button beside **Skills**, and its icon in the collapsed rail) that lists the **Agent definition** catalog — one row per definition the ACTIVE **Space** can see, so project-level rows AND the global (user-level) ones — and edits each one's **Agent override** (model / thinking / tools, ADR 0066). It is the ONE Agent surface: Settings has no Agents section, and two surfaces editing one app-global config is the confusion the single surface exists to remove (a per-row "this is a per-Space override" checkbox was considered and rejected as a confusion of its own — there is no per-Space layer; the override map is global, so the Space decides only which definitions get LISTED, never which overrides apply — ADR 0066). Each row prints the value AND the layer that supplied it (`override` / `file` / `Inherits parent`), resolved in Rust by the same function a real dispatch runs rather than derived in the renderer (ADR 0068) — so a row cannot disagree with how the resolver layers the fields, though its values are the LAST FETCH's answer (an edit lands in the store at once while the resolver's columns lag until the catalog refetches, which is why they are headed `runs`), and `Inherits parent` means only "nothing below the explicit `subagent` param spoke", never "the child will inherit". The modal is also where **Shadowing** is disclosed on the Agent side (as plain text on the winning row, never as its own row — ADR 0065) and where an orphaned override's remove button lives (ADR 0023's one cleanup path, reachable WHEN A SPACE IS OPEN — with no Space the modal suppresses the orphan block, because its discovery read only sees the user roots and cannot prove a key stale). The word names the *definitions*, never the **Agent** (the conversation partner) and never a **Subagent session** — which keeps every name and surface it has today (`SubagentDelegatingCard`, `SubagentTranscript`, `SubagentModals`, `usePendingSubagentRequests`).
_Avoid_: Subagents (the Settings section's old label — it named a session type the page never listed; that section is deleted), Agents panel, agents list, the agents page (Settings has none), subagent picker (a **Subagent session** is dispatched by `agentName`, not picked here), Agent config, model preset, subagent default model (all three once belonged to the **Subagent model override** entry, which this concept absorbed when the map grew its three fields)

**Agent override**:
One **Agent definition**'s entry in the app's settings — the flat `settings.json` map `agentOverrides` (agent name → `{ model?, thinking?, tools? }`, ADR 0066), which replaced the single-field `subagentModels` map the backend still folds in on read. Keys are matched case-insensitively (ASCII only, mirroring `eq_ignore_ascii_case`), ONE entry per agent survives a write (a case-fold twin is dropped), and the map is GLOBAL — no Space can hold a different answer. Field ABSENCE is the only meaning of "this override does not speak": `null` never goes on the wire, an empty `tools` list writes no key at all, and an entry emptied of fields is deleted with it (ADR 0067) — so no override can give a **Subagent session** zero tools, a capability the explicit `subagent` tool param keeps exclusively. Layered between the explicit `subagent` tool param and the definition's frontmatter (explicit > override > frontmatter > parent defaults — ADR 0023, each layer supplying each field independently); a stale override degrades to the next layer and never fails the dispatch, and the agent's markdown file is never modified.
_Avoid_: Subagent model override (the map's pre-trio name and its single field), per-Space override (no such layer exists), `subagentModels` (the legacy key the backend folds, never the live one)

**Provider**:
A user-managed model endpoint in the app's settings (`settings.json` `providers`: `{ id, name, baseUrl, apiKey, api, keyUrl? }`) — the desktop's SOLE model source (ADR 0014): each provider's models are discovered live from its endpoint, and its `api` field selects the endpoint FLAVOR — the wire the harness speaks AND the discovery mode (ADR 0024 + ADR 0026): `openai-completions` (default — `GET /models` discovery, OpenAI chat-completions wire) / `anthropic-messages` (Anthropic `GET /models`, Anthropic Messages wire) / `openai-responses` (OpenAI `GET /models`, Responses wire) / `litellm` (LiteLLM `GET {base}/model/info` discovery, OpenAI chat-completions wire — the `litellm` value is a discovery mode, NOT a fourth wire). The base model catalog is empty; a provider that discovers 0 models still shadows the base for its id (a no-op with a single source).
_Avoid_: Connection, model source, LLM endpoint

**Thinking level** (a LiteLLM `reasoning_effort` level):
One entry of a LiteLLM-discovered model's `thinking_levels` (e.g. `none` / `low` / `medium` / `xhigh` — the model's own vocabulary, surfaced VERBATIM from `model_info.reasoning_effort_levels`, ADR 0026). Distinct from the desktop's own thinking-level vocabulary (`off` / `low` / `high` / `xhigh`): a `litellm` provider's selector shows the proxy's words and sends the chosen level onto the wire as `reasoning_effort` AS-IS (no `off`↔`none` normalization). The per-model remembered level (`defaultThinkingLevels`, keyed `provider/model`) already handles the cross-vocabulary case.
_Avoid_: reasoning effort (the wire param name, not the UI term), thinking budget (the Anthropic mapping)

**Known provider**:
A built-in provider template in the desktop's known-providers catalog (a Rust constant seeded from the ZCode builtin provider catalog, ADR 0024) — `name` + `base URL` + `wire API` + `key-management URL`, offered in the Settings' Providers section as a picker. Picking a template adds a PRE-FILLED **Provider** row (empty API key — the user pastes the key); the template itself is not a provider (it stores no key and discovers nothing). The user's provider list remains the sole model source.
_Avoid_: Built-in provider (that would read as a model source), provider preset, provider template (the user-facing term is "known provider")

**Permission prompt**:
The Client's UI response to the native harness's in-process **permission gate** (the `permission-request` event before a tool call the **Beyond-boundary policy** sends to `Ask` — ADR 0010/0030) — the user approves or denies the tool call. Its title names the thing being reached for (`permission_title`: `read ../../.ssh/config`, `grep SECRET in /tmp`, `bash rm -rf …`). A `Deny` is NOT a prompt — it is a tool-result error that never reaches the UI.
_Avoid_: Approval dialog, consent prompt, confirm

**Boundary**:
The set of directories a **Session** treats as "in bounds", computed once per session by `agent::boundary` — `read_roots(cwd)` (the canonical `cwd` FIRST, then the user- and space-level **Skill** / **Agent definition** discovery roots) for the read direction, and `write_roots(cwd)` (the canonical `cwd` ONLY) for writes. A SET and not the `cwd` alone because `space_roots` walks up to the repository root, so a repo-level `.agents/skills` is outside a package `cwd` yet must be readable; the asymmetric seed is deliberate — reads are granted the agent dirs (ADR 0029's whole point), writes never are. `roots[0]` is the relative-path join base. Containment is "under ANY root", decided by the canonicalize-then-check in `FsBackend` (shared by gate and executor so they cannot resolve `..` or a symlink differently); an EMPTY root set fails closed, and the unrestricted floor is an explicit `/` root (`boundary::UNRESTRICTED`). Orthogonal to **Trusted Space**, which decides whether a prompt is shown, not what is in bounds.
_Avoid_: Sandbox root (the pre-ADR-0030 single `cwd`), allowlist, whitelist, cwd (one root of the set, not the set)

**Beyond-boundary policy**:
The user's per-direction choice — `FilePolicy { reads, writes, shell }` in `settings.json` (wire key `filePolicy`), each an `AccessPolicy` of `Sandboxed` / `Ask` / `Allow`, **defaulting to `Allow`** — that decides what happens to a file access landing OUTSIDE the **Boundary** (inside it every policy allows). Resolved by the one pure function `decision_for` into `Allow` / `Ask` / `Deny` / `Confine`: `Sandboxed` REFUSES a path-param tool and CONFINES `bash` (a Landlock ruleset, Linux-only, fail-closed — refusing commands would disable the shell), `Ask` prompts unless the Space is **Trusted**, `Allow` is silent and unlogged. `bash` has no path to judge, so it is always beyond. **Trust suppresses prompts but never widens a deny.** Reads are gated by the Boundary; the EXECUTOR is unrestricted at `Ask`/`Allow` (`boundary::executor_roots`), and writes are refused only in the four user-level agent dirs (`boundary::protected_dirs`) — in every policy, a guard-rail and not a security boundary (ADR 0030).
_Avoid_: Sandbox mode, permission level, access control (too generic), strict/normal/permissive (the UI words are `Sandboxed` / `Ask me` / `Don't ask me`)

**Lenient deny-list entry**:
One `boundary::protected_dirs()` member held even when its directory does not exist yet, canonicalized to its nearest EXISTING ancestor with the missing components reapplied — so a **Session** that recreates `~/.pi/agent/agents` is refused writing into it immediately, with no restart — **unless nothing on its path resolves**: an entry whose whole path cannot be resolved (no existing ancestor to peel to) is kept raw and does not refuse a canonical target. The asymmetry is the whole point: the DENY-list is lenient because a dropped entry silently UNPROTECTS the agent's own instructions, while the **Boundary**'s read roots stay strict because a lenient root would silently WIDEN what is readable. Because an entry may name a path that does not exist, the comparison that consumes it must canonicalize BOTH sides leniently — a strict `canonicalize()` on an entry that is still missing simply fails, and a failed compare is a silent non-match, which is the same hole the entry was kept to close.
_Avoid_: missing dir (it is not missing from the list, only from the disk), stale deny-list, protected root (the read roots are a different, strict set)

**Trusted Space**:
A Space flagged as trusted — its Sessions (including Subagent sessions) have the **Permission prompt** SUPPRESSED for whatever tool call the **Beyond-boundary policy** raises. A `Deny` and a `Confine` are untouched and an access inside the **Boundary** prompts nothing anyway, so trust is a suppressor of prompts and NEVER a widener (ADR 0030's precedence rule). `sudo_exec` (its own confirm + password modal) and `ask` (a `select` request, not a confirm) are unaffected. Because all three policies default to `Allow`, a prompt exists only where the user set a direction to `Ask` — so trust bites today only in combination with `Ask` (ADR 0010, as amended by ADR 0030). Trust is stored per-Space, defaults to off, is fail-closed (no Space row = untrusted), and is enforced in the native harness's in-process permission gate.
_Avoid_: Auto-approve mode, trust mode, yolo mode

**Config option**:
A per-session selector the harness re-synthesizes in-process from the `ModelCatalog` (the model / thinking-level selectors — the `synthesize_catalog_config_options` shape) and the Client updates via the `set_session_config_option` command. The harness is the source of truth: the Client does not persist config options; a resume re-synthesizes fresh state from the stored model + the catalog.
_Avoid_: Model list, model picker, settings, preferences

**Thinking block**:
The collapsible UI unit that shows the agent's streamed internal reasoning (the harness's streamed thinking events) — one per contiguous thinking run, collapsed by default with a live one-line summary while streaming. In the transcript data model it is a message of kind `agent-thought`. It is NOT inside the **response band**: the thinking stays a bare **transcript row** so the surface reads as the answer.
_Avoid_: Thinking tokens (reads as a token-count statistic), reasoning block (ZCode's term; the Client's UI says "Thinking…"/"Thought")

**Response band**:
The surface an assistant reply rides — the user message band's own treatment (`rounded-xl bg-composer px-3 py-2`, full column width, no border) applied to an `agent-text` message, so a reply and the prompt it answers wear the same **Palette** token rather than a copied hue. The name is for an existing treatment on a new row type, not a new surface. A copy button sits OUTSIDE it, below, copying the reply's raw markdown and never the thinking.
_Avoid_: bubble (the chat-app shape this deliberately is not), message card, agent card

**Attachment**:
An image staged in the composer (via clipboard paste, the file picker or drag-and-drop) that is sent with the next prompt. Previewed as a removable thumbnail in a strip above the composer's textarea; persisted inline in the user message's payload. Staging one inserts an **image marker** into the draft, and a send clears the thumbnails immediately while holding the attachments aside so a failed turn can restore them.
_Avoid_: File, image, media, clip, paperclip

**Image marker** (`[image #N]`):
The text a staging action inserts at the caret so a prompt can name a specific attachment. `N` counts the attachments **of that message**, never the session — the only reading true on the wire, because the harness pushes the text block then the images in send order as `image_url` parts, so "the Nth image of this prompt" is what a model can resolve. Sent as part of the prompt. Removing an attachment renumbers the markers so the number never lies about which image it names. Immune to the `#` **Mention** grammar, which leaves an unmatched token verbatim.
_Avoid_: image placeholder, attachment token, session-wide numbering (the counter the wire cannot verify)

**Theme**:
The light/dark **mode** of the Client's UI — the persisted `theme` setting (`system` / `dark` / `light`), resolved to an `AppTheme` (`zai-light` / `zai-dark`) by `src/lib/theme.ts`, where `system` follows the OS scheme. A Theme selects *how light or dark the app is*; it says nothing about which hues the app uses — that is the **Palette**. The two are separate settings (ADR 0027).
_Avoid_: Color scheme, skin, appearance (the Settings *section* that hosts both controls), style

**Palette**:
The Client's **color scheme** — the persisted `palette` setting (`zai` / `dracula`), applied as a `.theme-<name>` class on `<html>` over the shared `.dark` token block. A Palette selects *which hues* the app wears; it is orthogonal to **Theme** (the light/dark mode), except that `dracula` has no light reading and therefore PINS the app dark, ignoring the mode — `system` included (ADR 0027). The syntax-highlight theme is DERIVED from the palette (Shiki `dracula` / `github-dark`), never a third setting.
_Avoid_: Theme (that is the mode), skin, color scheme (ambiguous between the two axes)

**Identity color**:
A color token whose hue encodes *what kind of thing this is* rather than decoration — the file-type descriptors (`--color-file-*`), git status (`--color-git-*`), usage-chart and context-breakdown scales, and the role chips (file/skill/command/session/plugin nodes). Because the hue IS the signal, an Identity color is never re-hued by a **Palette**: `.theme-dracula` inherits these from `.dark` (deriving them from Dracula's 8 hues would make a `.py` chip indistinguishable from a `.json` one). A Palette-owned structural token, by contrast, is always restated per palette — see ADR 0027's completeness consequence. The **row token family** is NOT one: a transcript row's hue encodes nothing about what the row *is*, so it is decoration and belongs to the **Palette** (ADR 0062, which also removed the unconsumed `--color-trajectory-*` family that used to be listed here as an identity family).
_Avoid_: Accent (a Palette choice), brand color, semantic color (the status hues — success/destructive/warning — ARE overridden per palette)

**Row token family** (`--color-row-icon` / `--color-row-verb`):
The two palette-owned tokens that colour a **transcript row**'s glyph and its verb — named for `TRANSCRIPT_ROW`, the class the tool rows, the **Thinking block**'s trigger and the `Changes` group share. They split by *role within a row*, not by row kind, so they carry no meaning and are decoration rather than an **Identity color** (ADR 0062). Aliased back to `foreground-subtle` / `foreground-subtlest` in every **Palette** except Dracula, which paints them `#ffb86c` / `#8be9fd` — the first being `--color-warning`'s own hue, accepted knowingly. A pending call keeps the shimmer, not the verb hue.
_Avoid_: trajectory colors (the deleted, unconsumed row-kind family), tool colors (the family covers the `Thought` row too), verb color (singular — there are two tokens)

**Transcript row**:
A single line of the conversation column that is not prose — a **Thinking block**'s trigger, a tool call's header, or a folded `Changes` group. All three render through the one `TRANSCRIPT_ROW` class constant: a plain row hugging its content on the transcript's content edge, with no band, no hover highlight and a hover-revealed chevron. The **row token family** and the **response band** are both defined in terms of it.
_Avoid_: tool row (only one of the three kinds), row band (a row deliberately has no band), trajectory (the deleted family's word)

**Skill**:
A directory containing a `SKILL.md` — YAML frontmatter (`name`, `description`, `disable-model-invocation`) + a markdown body (instructions, optionally referencing bundled files) — discovered from the standard locations (the user home `~/.agents/skills` + `~/.pi/agent/skills`; the Space/project's `.agents/skills` + `.pi/skills` walked up to the repository root). The **Agent harness** advertises every **model-visible** Skill's metadata (name, description, location) in the system prompt and loads its full instructions on demand (progressive disclosure) — via the `list_skills` / `read_skill` tools, which resolve a skill by **NAME** and sit deliberately OUTSIDE the **Beyond-boundary policy** (`POLICIED_TOOLS` does not list them): they keep ADR 0029's per-skill containment, so a user-scope skill still loads at `Reads = Sandboxed` and a skill can never read a sibling skill. The user-level skill dirs are inside the read **Boundary** (readable) and on the write deny-list (`boundary::protected_dirs`) — a session may never rewrite its own global instructions, in any policy. In the Client, a skill is explicitly invoked with a `$name` **Mention** — the route that reaches a **model-hidden** Skill too whenever the **Mention** grammar can carry the name (see **model-hidden**); the Client expands the mention into the skill's full content on send, before the message is recorded (ADR 0013).
_Avoid_: Plugin, command, prompt template

**Shadowing** / **shadowed**:
The exclusion of a **Skill** (or **Agent definition**) because a nearer discovery root already contributed the same **name** — the winner is the nearest root (Space before user, innermost project level before outer), and the loser is *shadowed*. A shadowed entry is **disclosed, not listed**: it stays unaddressable by `read_skill` / `list_skills` / `$name` **Mention**, because NAME — not path — is a resource's identity (ADR 0065). Distinct from a **Duplicate**, which is silent.
_Avoid_: overridden, masked, conflict, collision (pi's word for the diagnostic, not the relation)

**Duplicate**:
An excluded entry that is NOT a **Shadowing** victim because it is not a different file: the same `SKILL.md` reached through two roots (collapsed on its canonical path, so a symlink farm contributes nothing) or a byte-identical copy present in two roots. Duplicates are collapsed silently and never reported — reporting a "hidden" Skill whose contents are the ones already listed would be noise.
_Avoid_: shadowed (the byte-identical case is not a shadow), dup (also names the IPC `mergeDedupeKey` concern)

**model-hidden** / **model-visible**:
The two audiences a **Skill** can have, set by the frontmatter key `disable-model-invocation: true` — verbatim from the Agent Skills spec, and recognized as a **YAML core boolean**: `true` / `True` / `TRUE`, with a trailing comment ignored — the comment separator is an ASCII SPACE or a TAB (`true # keep it out` is the boolean, `true#no-space` is one plain scalar and hence a string; pi's own YAML parse tests `=== true`) — while `yes` / `on` / `1` / a quoted `"true"` are NOT booleans and leave a Skill model-visible. A model-hidden Skill is **unadvertised and unresolvable by name**: absent from the `<skills>` section, from `list_skills`, and rejected by name by `read_skill` (ADR 0036). It is NOT confidential, and the ceiling is documented rather than fixed: `boundary::read_roots` grants the **Boundary** the Skill discovery roots themselves (ADR 0030's reason for loading a skill at `Reads = Sandboxed`), so `read` / `ls` / `grep` on a model-hidden Skill's path stay IN BOUNDS and silent in every policy, and `bash` reaches them outright at `Shell = Allow` — the shipped DEFAULT, which makes it the commonest route of all — the flag controls the **Agent**'s attention, not the filesystem. Available to the user through the `$name` **Mention** WHENEVER the **Mention** grammar can carry the name (ADR 0031's token shape); a model-hidden Skill whose name is outside that ASCII grammar (`has space`, `a_b`) has no `$` route the Rust side will PROMISE to anyone (the single quirk the Rust refusal is worded around: the Client matches by a JS case-FOLD, so a name written with U+212A KELVIN SIGN folds to `k` and still expands even though `skills::is_mentionable_name` rejects it), and the Skills-dialog **tooltip** says so plainly instead of promising a dead token — and the row itself now refuses that insert too: such a row is LISTED (discovery stays total) but INERT, out of the tab order, its click and Enter doing nothing, and it says why in a tooltip that carries no `$` glyph (issue #10). Marked in the Skills dialog either way.
_Avoid_: hidden (alone — reads as a UI visibility property), disabled (the flag name invites "the skill is disabled"; it isn't — it is fully user-invocable), non-model-invocable (collides with "a skill is invoked with a `$name` Mention"), private, internal skill

**Mention**:
The composer affordance that names a resource by a sigil prefix — `$` a **Skill**, `@` an **Agent definition**, `#` an **MCP server** (`#` ships OFF behind a setting, ADR 0032). Its defining act is EXPANSION: on send the Client replaces nothing and APPENDS a block (`<skill>` hard — the injected text IS the task; `<agent>` / `<mcp>` soft — a hint naming a resource the **Agent** still reaches with its own tool call), and that expanded text is what is sent, persisted and re-hydrated, so the live bubble, the stored row and the model's input are byte-identical and `mergeDedupeKey` matches across a resume (ADR 0031). A token that matches no catalog entry is left VERBATIM, and the exact-match lookup is what makes an interpolated name tag-safe — safety that collapses if matching ever becomes prefix/fuzzy.
_Avoid_: Slash command, trigger, tag, reference. Critically NOT the `?` **File completion**, which expands nothing — do not call `?` a mention or route it through `expandMentions`.

**Composer command**:
The fourth composer prefix: a `/name` token the **Client** intercepts on send and runs as a **Client**-side action. It is the third composer SEMANTICS — a **Mention** EXPANDS into a block, **File completion** inserts a PATH, a Composer command is CONSUMED: nothing is sent, no user row is persisted, so there is no `mergeDedupeKey` to match (the deliberate, bounded exception to ADR 0031's byte-identity contract — which governs text that IS sent). `/compact` is the first one (ADR 0044). A leading `/` claims the message and trailing text becomes args, so an UNMATCHED `/foo` MUST fall through as prose — load-bearing, because a **File completion** row consumes its `?` and can legitimately start a draft with `/etc/hosts `. Matched by EXACT name, like a **Mention**.
_Avoid_: Slash command (the shape, and `Mention`'s entry rejects this word for a Mention), prompt (it never reaches the **Agent**), Tauri command (the IPC surface — a different "command" entirely), extension command (pi's word), console command

**File completion**:
The composer's `?<query>` affordance: it offers file paths — from the active **Space**'s **Listing**, or, for a token that names a directory elsewhere, from ONE directory's **Directory completion** rows — and on selection REPLACES the token with the file's path plus a trailing space (Space-relative for a **Listing** row, ABSOLUTE for a **Directory completion** row; the `?` is consumed by a file row either way). The trailing space is LOAD-BEARING: it is what ENDS the token, so with the caret sitting after the space no token forms there and the next keystroke types prose rather than extending the path the user just picked. It is also what a **Directory completion** row does NOT do: a directory keeps the `?` and appends `/` with no space, because its selection continues the descent. It is deliberately NOT a **Mention** — nothing is expanded, no block or chip exists, and `expandMentions` / `splitMentionBlocks` / `mergeDedupeKey` never see it — because it inserts a PATH so the **Agent** opens it with its own `read`, which IS Boundary- and policy-gated. Injecting contents instead would let the user's own typing bypass the **Beyond-boundary policy** (ADR 0033). SCOPE is decided by the token's own first characters, and since ADR 0035 that guarantee lives in the GRAMMAR, not only the catalog: a token that begins with nothing, or with a plain name, is a **Listing** query and stays inside the **Space**; a token beginning `/`, `~/`, or a Windows drive root (`C:/`) is a **Directory completion** and leaves it. `~` is therefore IN the token charset now — expanded in the FIRST position only, by `skills::home_dir()`, and never for another user (`~otheruser` cannot even form a token — the root requires `~/`). `~` mid-token forms NOTHING: `?a~b` opens no picker, because `~` lives in the absolute shape's ROOT only and is not in the relative charset. The absolute shape additionally admits SPACES and a drive `:`, which the relative one never does: `?foo bar` must not eat the sentence, while `?~/Library/Application Support/…` has to be typeable and a Windows descent MUST be able to re-form the `C:/…` a directory row just inserted, or it dies after one level. The cost of admitting spaces is real and accepted: prose typed after an absolute token is ABSORBED into the query until a newline, and it lands inside the SEGMENT the rows are filtered on. The safety is therefore NOT that an absorbed tail cannot match: the matcher is a SUBSEQUENCE test, so the DIRECTORY'S CONTENTS decide. Usually nothing matches, because the tail makes the segment longer than any entry name, and the picker renders nothing and `Enter` sends. But a directory holding `todo list of items.md` DOES match `?~/notes/` plus the prose ` list of items`: one row renders, `Enter` inserts it, and the prose goes with the token. That is accepted because it edits the user's own draft and not a policy, and because refusing spaces would refuse `~/Library/Application Support`. A `?` anywhere in the prose destroys the token outright (`?/etc/pas?x` forms no token at all), which is the same degradation as any other unformable token. Prose carrying a `/` moves the DIRECTORY the picker reads, so one real read is issued for a directory that cannot exist, and `Enter` is held for that one round trip before the text goes out. Every other property is unchanged across both modes: it inserts a PATH, it preserves case, and `?/` now lists the root directory, where on `main` the same token was a **Listing** query that matched every multi-segment path in the Space. That is a change of SCOPE, not the repair of a dead key. WHICH files appear is a SEPARATE axis, decided by the **Listing**'s visibility rule — the repo's own ignore rules (ADR 0034) decide everything by convention, and the app holds exactly TWO rules of its own, neither of them a convention. The first is the VCS metadata prune: a directory named `.git`, `.hg` or `.svn` is never LISTED as a row and its subtree is never walked, at any depth below the queried root, because `git` cannot ignore its own `.git/` and so no ignore file can be asked to exclude it. The queried directory's OWN name is never a prune decision, so `?/repo/.git/` lists `objects`, `HEAD` and `config`: the prune is a rule about what a directory CONTAINS, exactly as a **Space** opened at `.git` has always listed it, and no row ever OFFERS `.git`, so reaching it takes typing (ADR 0034's `depth > 0` wording is the accurate one; ADR 0035 records the refusal to do otherwise). The second is a REPRESENTABILITY filter: a NAME carrying `?` or a newline is refused by both walks, and a directory with such a name is not descended into either, because those are the only two bytes the token grammar cannot carry: that is a limit of the grammar, not an opinion about the file, and it consults no convention, no name, and no project policy. What ADR 0034 deleted stays deleted: no project-convention skip-list (`node_modules` or anything like it) is hardcoded. THESE rules decide an outside directory's rows too, one level deep — Directory completion reuses this engine rather than carrying a second opinion (ADR 0035). EVERYTHING ELSE IS THE REPO'S CALL, dot-named or not — `.github/workflows/ci.yml` is tracked, not ignored, and IS listable here. It PRESERVES case (`?REA` → `README.md`) — unlike a Mention's lowercase-only token — because the insertion is VERBATIM, with no lowercasing rule for a path. Its inserted text then obeys the Mention grammar exactly like hand-typed text: a path holding `$name` expands, and so does an `@name` or `#name` wherever the glyph follows whitespace or a line start, which an out-of-Space filename can supply (`notes @draft.md`). Expansion needs a resource of that EXACT name, so it is the pre-existing grammar at work and not a surface of `?` (ADR 0033, ADR 0031).
_Avoid_: File mention, path mention, file picker (that is the composer's `+` image dialog), autocomplete

**Directory completion**:
The `?` picker's out-of-Space mode: when the token begins `/`, `~/`, or a Windows drive root, it lists exactly ONE directory — THE DIRECTORY PART of the token, everything up to and including its last `/` — instead of consulting a **Listing**. That is the token's parent while a last component is still being typed, and ITSELF the moment the trailing `/` is; the client sends the directory part and never the whole token, so "parent" is not the operative word in the shipped path. It is NOT a Listing, and it shares three things with one: the visibility engine, the entry cap, and the same cache machinery keyed differently (the key is the directory prefix, the LEFT prefix is evicted, so the rows of a directory are read once per visit rather than once per keystroke). Nothing is walked outward, and no project-convention skip-list exists: the two app-level rules the Space walk carries (the VCS metadata prune and the representability filter) are the same two rules here, because it is literally the same engine one level deep (ADR 0034's visibility rule reads `.gitignore`/`.ignore`, and above a repository there is nothing to read — which is *why* this mode is a peek and not a home-wide walk, since a usable home-wide listing would require reinstating the hardcoded skip-list ADR 0034 deleted). Rows carry an ABSOLUTE `insert` path and an abbreviated `display` (`~/…` under home): the draft receives the absolute path because NOTHING ON THE COMPLETION PATH expands a tilde, and teaching `FsBackend::resolve` to would put a normalisation rule on the **Boundary** seam (ADR 0035). The one place in the app that DOES expand one is **External open**, which is not a Boundary seam (ADR 0051). A DIRECTORY row keeps the `?` and appends `/` so descent continues; a FILE row consumes it and appends a space, ending the token, as file completion always has. A Windows drive root is refused on Unix and macOS: `expand_completion_root` returns nothing unless the expansion is ABSOLUTE, so no query is ever resolved against the process working directory and no `insert` is ever relative to it. It follows symlinks, where the Space walk refuses to — one level deep there is nothing to contain, and out here `~/bin` and `/etc/os-release` ARE symlinks — while `FsBackend` still judges the canonicalised target, so the picker widens no access. It is deliberately not a search: it helps only when the directory is roughly known. Its REACH is the surprising half: the rules are read from the queried directory AND its ancestors, and the nearest ancestor holding a `.git` is the git ROOT of the read, so on the common layout where `$HOME` is itself a dotfiles repository, `~/.gitignore` and `~/.git/info/exclude` decide every `?~/…` peek, with no note in the listing and `truncated` still false; nothing above that `.git` reaches in, and `core.excludesFile` never does (ADR 0035). THREE behaviours fall out of the machinery and are accepted rather than polished away: after a directory selection the picker renders NOTHING for the duration of one fetch, and **`Enter` is HELD for that one round trip** rather than sending the raw token to the model, because a blank picker removed the intercept that used to catch the press (a REJECTED or empty read counts as settled, so a directory that cannot be read never holds `Enter`); the rows of the directory you left must never be insertable into a token that no longer names them, which is why the render gate is `rows || note` and the box stays empty; and leaving a directory evicts it, so re-entering one reads it again instead of serving the rows you left behind.
_Avoid_: path browser, file browser, global completion, fuzzy find, home walk (the thing this deliberately is not)

**Listing** (the file completion's):
The set of **Space**-relative paths the `?` picker offers at one time — walked once per Space, capped, `/`-separated, reported with a `truncated` flag, and cached in the renderer so filtering stays synchronous. It is a CATALOG the composer filters, not the filesystem and not the **Boundary**. Three independent axes decide it, and collapsing them is the standing hazard (ADR 0034): **scope** (where the walk roots — the Space only), **visibility** (which files may appear — TWO sources, and the second is not negotiable by the repo: the repo's ignore rules (`.gitignore`, `.ignore`, `.git/info/exclude`) AND the TWO rules the app holds itself, which are the same two the **Directory completion** engine applies because it IS this engine one level deep: the VCS metadata prune, which removes a directory named `.git`, `.hg` or `.svn` at any depth below the Space root and is the ONE naming rule no ignore file can ever speak for (`git` does not ignore its own metadata), and the representability filter, which refuses a NAME carrying `?` or a newline because the token grammar cannot carry those two bytes and prunes such a DIRECTORY's whole subtree for the same reason. Neither is a convention, a project policy, or a skip-list in the sense ADR 0034 deleted; EVERY OTHER dot-**directory** is the repo's decision, so `.github/`, `.vscode/`, `.claude/` and a project's `.agents/` are listed unless an ignore file excludes them, and dot-**FILES** are kept, so `?.env` completes unless the repo ignores it — so the Listing is neither the tracked set nor the whole tree, because untracked-but-not-ignored files are listed too), and **reach** (where those rules are read from — the repo's own directories, never the user's machine-wide git config, so two people on one Space get one listing; the ONE accepted exception is that `parents` reads ancestor `.ignore` files, and `.ignore` is not gated by the `.git` barrier the git matchers are, so an `~/.ignore` above the repo root DOES apply while a `~/.gitignore` there does not — ADR 0034. "Above the repo root" is doing real work in that sentence: when `$HOME` IS a repository, it is the repo root, and its `.gitignore` and `.git/info/exclude` decide every Space under it.)
_Avoid_: file list, file index, tree, cache ("cached" is a property of a Listing, not the thing), "the files", Directory completion (a different mechanism — one directory, on demand, cached per directory prefix rather than per Space)

**Attention alert**:
The OS notification the Client raises when a **Session** has been paused on the user for the configured delay (`attentionAlertDelaySecs`, default 15s) — one at a time app-wide, its body naming the **Session** (title → **Space** folder name → `A session`; a **Subagent session**'s gate is its PARENT's pause — keyed to the parent, ranked at the parent's position, ADR 0040 amended 2026-10-13). Exactly two **attention triggers**, both derived from the same rule as `sessionStatusOf` so an alert can never disagree with the UI: **settled** (a **Session**'s turn ended — a PULSE that exists on the single snapshot where `inTurn` fell, and is never re-delivered) and **waiting** (any **Session** anywhere holds an `ask`/`confirm`/`password` request or a **Permission prompt**), waiting ranked ahead of settled whenever both are owed. It fires ONLY while the window is unfocused, and a focused window drops it rather than holding it (ADR 0038); the countdown runs in the **Supervisor**, never in the renderer (ADR 0039). A **Stalled session** is never settled — a Worker crash resolves the in-flight turn exactly the way a real finish does.
_Avoid_: Notification (that is `mcp::rpc::parse_notification`), toast, reminder, ping, idle alert (this is a delay from the pause, not an idle timer — nothing measures reading time), background alert

**Announced pause** (the memory's `spent`):
An **attention trigger** this renderer has already alerted on, held in a SET so that one alert per pause holds for EVERY pause owed at once: each entry mutes only its own pause, and each is forgotten on its own evidence — a new turn beginning, or that gate going away — so the NEXT pause alerts. It is renderer memory and nothing more: the **Supervisor** is never told which pauses were announced, only what to count down, so the set lives exactly as long as the renderer that holds it (a reload wipes it, and a question that already alerted alerts again — accepted, ADR 0038). Being announced is not the same as being the live countdown: the announced set survives an abort, a disarm, and the setting being switched off.
_Avoid_: spent slot (it is a set, and a single slot there was a real defect), muted session, seen pause, acknowledged (neither the **Agent** nor the **Supervisor** knows the alert was delivered)

**Activity signal**:
Deliberate input to the app's CONTENT while an **Attention alert** is armed — `keydown`, `pointerdown`, or `wheel` at the window level, captured so a modal cannot swallow it. It disarms the alert. Window blur is NOT one (the user leaving is what the alert exists for), neither is mouse motion, programmatic auto-scroll, or a click on the frameless window's own controls (ADR 0038: Minimize means the user is leaving, not reading).
_Avoid_: User activity (undefined scope), interaction, input (the composer's), idle reset

**Chrome controls**:
The three buttons at the right end of the frameless window's own top bar (`App.tsx`'s `data-testid="chrome-bar"` — the drag region that replaces the native titlebar), immediately outboard of the window controls: the Settings gear and the two pane collapse toggles (`ChromeControls`). They belong to the WINDOW, not to the surface each one hides, so they render in both collapse states and the panes themselves carry no controls — the sidebar's footer gear and both bottom-corner toggles are gone, along with the collapsed sidebar rail's second copy of the gear. One control per job, in one place, so nothing teleports when a pane collapses. They sit OUTSIDE the window controls' attention-alert exemption on purpose — opening a pane or Settings is a person coming back to work (ADR 0038).
_Avoid_: window controls (Minimize / Maximize / Close — a different component, immediately inboard), pane controls (what the two toggles are, not the cluster), toolbar (a bar of buttons is not a toolbar), sidebar footer / corner toggle (where all three used to live)

**Side pane**:
The resizable frame on the RIGHT of the workspace (`SidePane`) — the user's "right sidebar". It is a status panel, not a tab strip: one data-gated section per surface that has something to show, currently the **Todo board** and the session title, plus the **session config block** pinned below the scroll area. Its width and its collapsed flag persist. It holds NO collapse control of its own — the toggle is one of the **chrome controls**, permanently at the window's top-right in both states — and there is no keyboard shortcut. The collapsed sliver is the room the **Todo rail** draws in, not the room that held a toggle. The frame may OPEN itself, on the 0 → >0 edge of an open **Todo board** (the parent's or a child's), and NEVER collapses itself: the user's toggle is the only thing that closes it (ADR 0042).
_Avoid_: right sidebar, inspector, sidebar (unqualified — the LEFT pane is the **Space**/**Session** list), drawer, panel, tab strip

**Session config block**:
The lines pinned to the bottom of the **Side pane** — Model, Reasoning when the session has it, Context, one per line — holding the session's model selector, its **Thinking level** selector and the context bar. The Reasoning line IS data-gated: it renders only when the session's config options carry a `thought_level` select with options, which is the same condition under which the harness synthesizes the option at all (`synthesize_catalog_config_options` omits it for a model advertising no thinking levels), so a model with no levels shows no dropdown rather than a dead one. The Model line and the context bar are NOT gated — a model selector is meaningful for any session, and the picker's catalog comes from settings rather than the session's option list. Pinned BELOW the scroll area, not inside it, so the **Todo board** scrolls and these stay reachable. They are the pane's only non-status content, and the composer no longer carries them: with the pane collapsed to its rail there is no way to change model or read context until it is expanded, accepted knowingly.
_Avoid_: composer toolbar (where they used to live), config row, status section (only the Reasoning line is data-gated — the Model line and the context bar always render)

**History window**:
The contiguous TAIL of one **Session**'s stored display rows that the Client's store (`useSessions.messages[sessionId]`) holds: the latest 500 rows on open, with 200 older rows prepended per scroll-up page (cursor: the `messages.id` of the oldest loaded row), plus whatever streams in live. The store is a WINDOW onto the transcript, never the transcript — so state that must not depend on how far the user has scrolled (the **Todo board**) is session state, not a scan of the window (ADR 0073). It is NOT the viewport (the virtualized list renders only the rows near it, out of the window), and NOT the Worker's provider transcript (`native_messages`, which a resume rehydrates in full). A resume resets it to the tail.
_Avoid_: page (one scroll-up fetch is a page; the window is what the pages add up to), viewport, transcript (the whole stored conversation), cache, buffer

**Todo board**:
One **Session**'s own `manage_todo_list` list, held in `useInteractive.todos` under THAT session's id — a **Main session** and a **Subagent session** each have exactly one, because each runs exactly one **Agent harness** (ADR 0041). The Client attributes a board by that id, never by the frame's `source` label (which is the constant `"native"` on today's transport); a **Subagent session**'s board is found by joining `useSubagents` on `parentSessionId`. A MAIN session's board is persisted (`sessions.todos_json`, written by the **Supervisor**, seeded on open / resume) rather than recovered by scanning the **History window** (ADR 0073). _Avoid_: todo column (the old `{main, subagents}` shape that mis-routed every board), subagent todos bucket, todo list (the tool's own word for the array of items), `native` (a transport label, never a name)

**Current todo**:
A **Todo board**'s live item: its `in_progress` entry, or — when none is in progress — its FIRST OPEN one (the next up), where OPEN means "not `completed`": `useMainTodoItems` casts any model-authored string into the status union, and the rule that decides both visibility and this fallback is that negation, so an item counts toward the count that opens the **Side pane** exactly when it can be the row. `undefined` only when the list has no open item at all — a fully-completed parent board beside a live child board renders no row. _Avoid_: active todo, running todo, WIP item, "the first `pending` one" (an open item is not necessarily `pending`)

**Reduced board** / **Full board**:
The two densities a **Todo board** renders at in the **Side pane**. A board is REDUCED to its **Current todo** when it must share the vertical space — the parent's board whenever any child board shows, a child's board whenever a second child board shows — and FULL (every item, all three states) when it is the only board at its level. The rule is one sentence: a board yields to the boards beside it. It is a render choice only — the store always holds the full list. _Avoid_: collapsed board (the pane's collapse is a different thing), compact mode, summary

**Todo rail** / **board mark**:
The collapsed **Side pane**'s readout (`TodoRail`): ONE **board mark** per **Todo board** — the parent's first, and only when it HAS a list, then one per running **Subagent session** *with a board*, in board order (a running child whose list has no open item has no board, so it draws no mark: the rail iterates boards, not **Subagent session** entries). A mark's state is its whole board's: **active** if any item is `in_progress`, **done** if every item is `completed`, and **waiting** otherwise. It replaced one mark per ITEM, because a glance at a 40px sliver asks "how many boards, and which one is live" — never "which item", which is what the open pane is for. _Avoid_: todo dots, progress strip, mini board (nothing of the board is drawn there), per-item marks (what this replaced), "the rail" bare (in this repo `rail` is also the collapsed sliver itself — `SIDE_PANE_RAIL`; the Todo rail is what draws INSIDE it)

**External open**:
Handing a URL or a filesystem path to the operating system's own default handler (`xdg-open` / `open` / the Windows shell), through the ONE seam `crate::open` behind the `external_open { href, cwd }` command — every Client surface that opens something outside itself calls it (ADR 0051). A scheme-bearing href goes to the OS AS a URL; a schemeless href is a PATH resolved against the **Session**'s `cwd`, and no **Boundary** check is applied to it, because the **Boundary** confines the **Agent** and never the user's own click. It is never a navigation of the Client's own webview — the local navigation-guard plugin makes that structurally impossible, which is the failure this seam exists to end.
_Avoid_: open in browser (a path opens in an app with no browser in sight), xdg-open (one platform's spelling of it), shell out, launch, external link (that is an href, not the act), deep link (a scheme-specific subset)

**Build** / **Upload** / **Publish**:
The three distinct endings a release pipeline can have, named apart because only one of them makes an update reachable. BUILD produces the bundles (`tauri build` → the installer + its updater payload + its `.sig`); UPLOAD attaches them to a GitHub Release; PUBLISH is the draft→published transition (`gh release edit --draft=false`) and is the ONLY one that makes the updater endpoint answer, because `GET /releases/latest/download/latest.json` serves the most recent NON-prerelease, NON-draft release and 404s otherwise. A release whose assets are uploaded but which is still a draft has downloadable files and an updater that reports `ReleaseNotFound` — which is why the pipeline publishes LAST, after the **updater manifest** exists. _Avoid_: release (all three at once — say which), ship, cut, push (the git act), "upload the release" (an asset is uploaded, a release is published)

**Updater manifest** (`latest.json`):
The ONE release asset the installed Client polls to learn an update exists: `{version, notes, pub_date, platforms}`, where each `platforms` key maps to a `{signature, url}` pair naming an **updater payload**. Written by exactly one job (ADR 0052), because every platform's build job wants a say in it and `tauri-action`'s merge is an unguarded read-modify-write. Its keys are the updater's own target spellings — `{os}-{arch}` (`updater_os()`/`updater_arch()`, so `darwin` not `macos`, `x86_64` not `amd64`) and `{os}-{arch}-{installer}`, which the client tries FIRST — so a manifest carrying only bare keys serves a `.deb` install the AppImage payload, which verifies its signature and then fails `install_deb`'s format check. Not to be confused with the `.sig` files it quotes (a minisign signature over the payload's bytes, base64 WITH newlines, hence `jq --rawfile`). The `url` names the **updater payload**, which on Windows and Linux IS the **Installer** a human downloads — the plugin sniffs the downloaded bytes (`infer`), never the URL's extension, so the raw `.exe` / `.AppImage` / `.deb` / `.rpm` installs fine from an update and that is what `createUpdaterArtifacts: true` emits (`bundle.rs`: the v2 targets need "no wrapping"). macOS is the exception: only `Archimedes.app.tar.gz` works there (the installer path opens a `GzDecoder` unconditionally, so raw Mach-O bytes fail), it is the one artifact `bundle_update_*` always writes, and a `.dmg` has no `.sig` at all and is never an updater payload. The `…AppImage.tar.gz` / `…-setup.nsis.zip` shapes are the deprecated `createUpdaterArtifacts: "v1Compatible"` artifacts and are NOT expected in this project's releases (ADR 0052, amended).
_Avoid_: release json, version json, update file, changelog (`notes` is a string inside it), latest release (the GitHub object this describes)

**Prompt queue**:
One **Session**'s ordered list of **Queued prompts** the **Client** holds while its turn is in flight, drained **head-first** by the **Flush** when that **Session** stops being busy. It lives in the renderer and nowhere else: the **Supervisor** never sees a **Queued prompt**, so `send_prompt_with_images`'s atomic `pending_turn` claim stays the one-turn-at-a-time invariant untouched — a queue entry becomes an ordinary `send_prompt` only at its own turn. Keyed per **Session** like `inTurn`, but DRAINED ONLY FOR THE VISIBLE **Session**: it drains when it is the **Session** on screen and that **Session** stops being busy, and it holds while off screen, draining only once it is on screen again and idle. (Not a gap — the **Flush** expands **Mentions** through the ACTIVE **Session**'s catalogs, so a background queue drained off screen would expand against the wrong **Space**.) It is NOT part of the **Session status** rule: a non-empty queue means the user has more to say, never that the **Agent** is parked on the user (see `sessionStatusOf`).
_Avoid_: outbox, backlog, pending messages ("pending" belongs to a **Gate**'s pending prompts), draft list (a **Queued prompt** has left the draft), `AgentLoop`'s `prompt_queue` (a DIFFERENT queue in a DIFFERENT process — see its entry)

**Queued prompt**:
One entry of a **Session**'s **Prompt queue**: the user's raw draft text plus its **Attachments**, an id, and whether it is being edited. It holds the RAW draft, never the **Mention**-expanded text — expansion happens at send time, so an edit between queueing and **Flush** cannot ship text the user did not write. It is NOT a transcript row and never becomes one until it leaves the queue: the user row is created by the send, so deleting a **Queued prompt** retracts nothing.
_Avoid_: queued message (a **Mention** expands into a message; this is a prompt not yet sent), provisional row, scheduled prompt

**Flush**:
The act of taking a **Prompt queue**'s head and sending it as an ordinary prompt the moment that **Session** stops being busy — the SAME composite lock the composer refuses on (`workingOrInTurn || blocked || compacting`, not `inTurn` alone, because a **Composer command**'s idle compaction locks the composer while `inTurn` stays false) — one per such edge, in queue order, so the queue drains one turn at a time. Below the composer a **Flush** is indistinguishable from a manual send: same `send_prompt`, same user row, same turn bookkeeping. A **Stop** does NOT flush and does NOT clear the queue — it cancels the in-flight turn only, so Esc means "stop this answer" and never throws away what the user typed.
_Avoid_: drain (the harness's `drain` DISCARDS its queue — the opposite act), auto-send, dispatch (the tool dispatch path), release

**Queue row**:
One row of the in-flow stack that renders a **Session**'s **Prompt queue**, sitting between the transcript island and the composer island as a third sibling of the same island column and wearing the composer's own tokens one step thinner. It carries the **Queued prompt**'s text behind a `Queued` label, with edit and delete as its only actions, and it is the ONLY place a **Queued prompt** is visible — nothing provisional is ever added to the transcript. Ordered head-first (the next to send sits nearest the transcript, the newest nearest the composer), so a row entering from the composer and a row leaving upward into the transcript both move in the direction their name implies. A row is never a **Transcript row** and never a **Response band**: it is a control, so its actions stay visible rather than hover-revealed.
_Avoid_: Queue bubble (this entry's wrong first draft — nothing floats and nothing is a bubble), queue panel (the **Side pane** owns "panel"), queue tray, pill, draft stack

**Harness prompt queue**:
`AgentLoop`'s OWN `prompt_queue` (Rust, in the **Worker**) — NOT a **Prompt queue**, despite the shared words. Nothing on the user path can put a second prompt into it while a turn is in flight (the **Supervisor** refuses that prompt before it is ever written), and `cancel_turn` DRAINS it, discarding whatever is in there, because a queued prompt must not start a fresh turn after a Stop. It exists for the **Subagent session** dispatch path and for turn bookkeeping, never for user-visible queueing. The two are one name across a process boundary, which is why the user-facing list is never called this.
_Avoid_: the prompt queue (bare — that is the **Prompt queue**), worker queue, internal queue (a queue is never "internal" enough to leave unnamed)
