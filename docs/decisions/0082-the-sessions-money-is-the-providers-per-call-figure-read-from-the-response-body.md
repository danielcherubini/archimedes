# The session's money is the PROVIDER'S per-call figure, read from the response BODY — and an unknown price renders as nothing, never `$0.00`

A session's USD figure is **the provider's own number for each call, read off the `usage` object in the response BODY** — `usage.cost` first, then `usage.cost_details.upstream_inference_cost`, then `usage.estimated_cost`, the **first present** field answering — carried as `Option<f64>` on `ProviderEvent::Usage`, pushed as one `cost_update` frame **per call** (a delta, never a total), summed by the frontend store, and rendered **as nothing at all** when no call ever reported a figure. Landed as four commits on `feature/harness-trust-and-cost`: `ada64f4` (the parsers read it), `405be65` (the loop and the subagent roll-up emit it), `4b802b9` (the store and the pane render it), `54ba649` (the shared formatter's `$0.0000` cliff, fixed as its own commit). Issue **#87**.

Two designs were rejected by name, and both are worth keeping in the same breath as the decision, because someone will re-propose each of them:

- **A static price table on `Model.cost_per_mtok_in` / `_out`** — the superseded on-disk plan's central decision, which this ADR does not silently inherit: it was measured out of existence. **The recipe, because a naive `grep` lands on a different number and reads this as an error:** `git grep -n 'cost_per_mtok' -- src-tauri/src src` prints **46** lines, and they decompose as **44 initializer lines** = **22** `cost_per_mtok_in: 0.0` + **22** `cost_per_mtok_out: 0.0` (i.e. 22 `in`/`out` **pairs**, which is the "22 construction sites" the grounding and the commit messages count) **+ the 2 field declarations** at `harness/catalog.rs` (`pub cost_per_mtok_in: f64` / `pub cost_per_mtok_out: f64`) **+ 0 reads**. The read count is its own command, not an inference from the others: `git grep -n '\.cost_per_mtok'` over `src-tauri/src` and `src` returns **0**. A price table is a figure **invented** rather than observed, which is this branch's defect class at its root; and it could not have been made honest anyway, because a cache-aware discount requires a cache split that ADR 0046 deliberately does not keep. The fields are **left in place** — deleting them is separate cleanup, and this diff is not about a field it does not need. That is a decision, not an oversight; nothing here is a half-finished deletion.
- **The `x-litellm-response-cost` HEADER** — this spec's own first draft, and still the label on the roadmap's T08 task row. Rejected because HTTP headers are committed **before the stream completes**, so on a stream the header carries the **pre-stream** value: zero, partial, or absent. **This app always streams** (`ModelOptions.stream` is "Always `true` for `complete()`"), so the header is the wrong seam by construction — LiteLLM #30816, #46364, #12689 and #26475, and its own pass-through contract page conceding the limit. The component headers (`-input` / `-output` / `-cache-read`) are worse still: non-streaming-only, so the header route forces either a partial figure or a second mechanism. This rejection is **verifiable rather than rhetorical**, three ways: **zero header reads were added** (`git grep -c '\.headers('` over `agent/harness/provider/` returns **no files at all** — the pattern is armed by the same command over `src-tauri/src`, which finds `mcp/http.rs`, `mcp/oauth.rs` and `web/net.rs`), `provider/transport.rs` has **zero diff** across all four commits (armed: the identical command shape over `d0b0a9b~1..d0b0a9b` prints that file), and the rejected design is **named in a shipped doc comment** so nobody rediscovers it — `cost_usd_from_usage`'s own opening lines read *"AMENDED: money arrives in the response **BODY**, on the usage object each parser already reads — NOT the `x-litellm-response-cost` header, which commits before a stream ends and so carries a pre-stream value"*.

**One stale label to distrust.** The roadmap's **T08 task row still says "read the cost header at the provider seam"**, and the decisions log records the same thing: *"The task table is the stale label; **D4 governs.**"* A reader checking this ADR against the task table will find a contradiction and should blame the table, not the code and not this document. (The roadmap and its follow-ups file live under `docs/roadmap/`, which is gitignored in this repo, so the durable copy of anything quoted from them is here.)

## Why this is #87, and why it is the thesis applied to money

The branch's thesis is that **the harness must not report an outcome it did not observe.** #93's violation was a report of an edit that was not the requested one; #94's was a discarded exit status; #92's was a guard-rail claim the code does not enforce. **#87 is a figure we did not observe being displayed as if we had.** The roadmap states the defect that way, and its sentence is worth having here because the roadmap is gitignored:

> **#87** displays cost fields that are structurally present and numerically meaningless (`0.0` everywhere), so "free" and "unknown" are the same number.

The spec's own framing is the reason this ADR exists as a task at all: *"That framing is also what makes one PR defensible to a reviewer: four commits, one thesis, and the ADRs are four applications of it rather than four unrelated rulings."* The task inventory scheduled two of those four ADRs (0079 for #93, 0080 for #94); #92's and #87's were named in no task, so the branch would have shipped three issues with rulings and one — the one whose defect reaches the user's wallet — with none. Numbers are by landing order (0079 #93, 0080 #94, 0081 #92, 0082 #87) and this file holds #87's number.

And this ADR has transferable content beyond the ruling, because **the branch's own defect class re-appeared inside its own fix** — in a formatter, three commits later, on two surfaces that neither of the two tasks that could see it owned. That story is its own section below, and it is the part of this document that generalises past money.

## The shape: cost rides the EVENT, not the `Usage` STRUCT

`ProviderEvent::Usage` became a two-field variant — `Usage(Usage, Option<f64>)` — and `struct Usage` gained **nothing**. Its `#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]` is unchanged, so **`Eq` survives**; its 25-line definition and its ADR 0046 doc comment are byte-identical. The event's own doc comment carries the reason and the `None` rule, because a tuple variant has no field name to document:

> The token usage (usually a trailing chunk) plus, when the provider priced the call, its cost in USD. `None` cost means the provider reported NONE — it is NOT zero and must never be rendered as `$0.00`; a `Some(0.0)` IS a figure and renders `$0.00` (D5). Cost rides the EVENT, not the `Usage` struct, so the Anchor type (ADR 0046) keeps its fields, its `Eq` and its doc comment untouched.

Three consequences, each with shipped evidence:

**1. Money never reaches the Anchor, and the change that bought that was the wide one.** `Compactor::record_usage` takes a `&Usage` and so never sees a figure. Putting `Option<f64>` **on the struct** would have dropped `Eq` and reached all **11** `&Usage { … }` anchor literals in `compact.rs` (re-measured: `grep -c '&Usage {' src/agent/harness/compact.rs` → 11, zero diff across the four commits). Money on the **event** instead touches carrier sites and none of those. The carrier-site counts, re-measured at execution with `git grep -c 'ProviderEvent::Usage' <rev> -- 'src-tauri/src' 'src-tauri/tests' | awk -F: '{s+=$3} END {print s}'` — the per-file counts summed, **not** `| wc -l`, which counts *files* (7 / 7 / 8) and is a different question. **One trap in the command itself, because the same trap produced a wrong number in this task's own plan:** passing a `<rev>` makes `git grep` prefix each line with that rev, so the count is **field 3**, not field 2 — `awk -F: '{s+=$2}'` on rev-qualified output sums the *file counts* and prints `0` for every revision. The arm check is the same summing form at `bdd9cef`, and it must print 28; if it prints 0, the pipeline is mis-armed and every result it produces is UNVERIFIED rather than clean:

| Revision | Carrier sites | Files |
|---|---|---|
| `bdd9cef` (base) | **28** | 7 |
| `ada64f4` (parsers) | **47** | 7 |
| `54ba649` (HEAD) | **57** | 8 |

Armed against the same summing form: the command at `bdd9cef` prints 28, so the pattern can hit and the counts are measurements rather than artefacts of a broken pipeline. **`ada64f4`'s message says "28 carrier sites" meaning the sites at its *base*, not at its own diff** — both framings are correct and neither is the other; this ADR uses the summed-site counts throughout. The trade to state plainly: **a wide mechanical change with no semantic reach beat a narrow one that would have reached into compaction accounting to move a display figure.**

**2. `a_cost_frame_leaves_the_context_usage_anchor_alone` is the falsifiable form of "money never reaches the anchor."** It seeds a `Usage` with `input_tokens: 4321, output_tokens: 100` **and `Some(0.0042)` on the same event**, asserts a cost frame really was emitted (the precondition, so the pin cannot pass vacuously), and then asserts `usedTokens == 4421`. Say what kind of pin it is, since the file says it: `record_usage` is unchanged by the task, so this **passes on write** — it is a **regression guard** against a later edit that routes money into the anchor while a cost sits on the same event.

**3. The cost term stays OUT of `emit_usage`'s guard, and that is a pinned decision, not an oversight.** The shipped paragraph:

> The guard below is deliberately **counts-only**: it must NOT gain a `|| self.cost_usd.is_some()` term. A cost with no token counts on either side would push `Usage(0, 0, Some(money))`, and `Compactor::record_usage` would write a ZERO **Anchor** — a compaction regression bought for a figure (pinned by `anthropic_sse_cost_with_no_token_counts_emits_no_usage_event`).

So **a cost with no token counts is DROPPED on every wire** — by three *different* mechanisms, because each wire has its own gate: Anthropic's counts-only guard above; the OpenAI-shaped `prompt_tokens` × `completion_tokens` pair gate (`sse_cost_only_usage_chunk_emits_no_usage_event`, whose comment adds that *"a cost-only emission path would make this a SECOND `Usage` producer and hand T09 money detached from the counts D4 pairs it with"*); and the Responses terminal shape (`responses_sse_cost_with_no_token_counts_emits_no_usage_event`). **Honest framing, because the pins carry it in the tree:** all three assert an **absence**, so they were green before the change as well as after. They are **regression guards, not RED pins** — three new behaviours were not proven by them, and pretending otherwise would be exactly the kind of claim this branch keeps having to walk back.

Anthropic reads the cost at **both** places it reads a usage object (`message_start`'s input side and `message_delta`'s output side) into one field, **last-non-`None`-wins**, so *"one that omits the cost does NOT erase an earlier figure — an absent field is neither a zero nor a retraction"*; `usage_emitted`'s exactly-once guard is unchanged and the cost is one more argument on that single push (`anthropic_sse_cost_is_emitted_exactly_once`). No request body changed on any wire: the OpenAI-shaped wires already send `stream_options.include_usage` when streaming, Anthropic accepts no such field, and Responses sends usage unconditionally.

## Deltas, not totals — and the grain mistake that makes totals wrong before they start

`TurnAccumulator` is constructed **once per MODEL CALL** — `let mut acc = TurnAccumulator::default();` sits inside the per-model-call scope in `harness/loop.rs`, below the call's `select!` and above `consume_stream` — **not** per turn. So "a per-turn total from the accumulator" is not a thing that exists. The same grain mistake is what `subagent.rs`'s **deleted** doc claim admitted, and the shipped replacement names both halves of it:

> The earlier text here claimed the suite "self-emits a per-turn `cost_update`" derived from a model `turn_end` usage; no such mechanism ever existed, and the grain was wrong besides — a turn spans several model calls.

Therefore: **Rust holds no accumulator.** One frame per call, emitted from inside the `Usage` arm, carrying that call's cost and nothing else; the cumulative object is the frontend's `useInteractive.cost[sessionId]`. The emitter's contract is stated in the shipped doc comment as three bullets, quoted in full because both sides of the wire pin them:

> - **A `None` cost emits NOTHING at all.** Absence is the wire spelling of "no figure"; the phantom `$0.00` is created by *emitting a zero*, so the only defence is not to emit. Rust never puts `null` on this bus.
> - **The value is ONE call's DELTA, never a running total.** The frontend store sums the frames, so re-emitting a total would double-count — and a Worker re-incarnation / `Resume` (which rebuilds this loop with no memory of the old figure) would make that unrecoverable. Hence there is deliberately no accumulator on `AgentLoop`.
> - **`-0.0` is normalised here.** `c + 0.0` maps `-0.0 -> +0.0` and leaves a real `0.0` untouched, so the bus never carries a signed zero (which the frontend would render as `$0.00`, since JS treats `-0 === 0`). This is NOT the `!= 0.0` filter that would eat a legitimate `Some(0.0)` — a real zero is still a figure and still gets its frame.

Pin: `two_priced_calls_emit_two_deltas_never_a_running_total` — two prompts on one loop, `Some(0.0010)` then `Some(0.0020)`, and the second frame must be `0.0020`, **not** `0.0030`. Those discriminating numbers are the whole point: a count-only assertion would be a tautology, which the implementer recorded and avoided.

Two consequences follow from the deltas contract and both are features stated in the contract rather than discovered later:

- **A totals contract would be unrecoverable across a Worker re-incarnation or `Resume`.** A fresh `AgentLoop` emitting totals into a **summing** store either resets the figure or double-adds it. Because the frames are deltas and nothing had to survive, **`Resume` continues the figure while a page reload does not** — correct behaviour with an honest limit attached (Honest limits 1).
- **The emission point is inside the `Usage` arm, not at a settle point**, and the shipped comment says why: *"An attempt that reported a `Usage` and then died was still billed, and its money must not be forfeited by a turn that never settles."* Pinned by `an_abandoned_attempt_that_delivered_a_usage_still_emits_its_cost`, which the implementer **mutation-proved** against the exact refactor that would break it (hold the cost, emit only when the stream settles): 1 frame instead of 2, RED. That is an **attributed measurement** — this ADR runs no `cargo`.

**A frame is not an `RpcEvent`.** `agent/events.rs` has **zero diff** across all four commits (armed: the same command shape over `08f18d2~1..08f18d2` prints that file) — no variant, no `kind()` arm — because the frame rides the `interactive-event` channel, which the Client routes off the payload's `event` discriminant (`App.tsx`'s `INTERACTIVE_EVENTS.costUpdate` case, and `src/lib/ipc/events.ts`'s `costUpdate: "cost_update"` long predates the emitter). The plan's drafted assertion for this was a **tautology** (a variant's `kind()` name can never contain `costUsd`), so `a_cost_frame_is_not_an_rpc_event` serialises every drained `RpcEvent` and greps the **wire** instead — the same discipline 0079 and 0080 record for their own rejected tautologies.

## Unknown is not zero, all the way down

One rule, three implementations, because the defect re-appeared at each layer one below the one before it: the wire was fixed, and the store re-manufactured the zero; the store was fixed, and the formatter re-manufactured it again (next section).

**The wire.** Rust **never** emits `null` and **never** emits a frame for a `None` cost — `a_call_without_a_cost_emits_no_cost_update_frame_at_all`. Absence is the wire spelling of "no figure". Note the asymmetry the plans had to spell out: the Rust wire type is `number`, the store entry type is `number | null`, and the `null` half is produced by a frame's **absence** — so `null` never appears on the bus even though it appears in the type.

**The store.** `combineSessionCost` makes **`null + null = null`**, and the shipped comment names what it replaced: *"the inline `(prev.cost ?? 0) + (p?.cost ?? 0)` this function replaced did exactly that, and it is why a session with no priced call displayed `$0.00`."* The sentence that makes this a decision rather than a refactor: **a bare rename that kept `?? 0` would have shipped `$0.00` under a new key name.** One plan asserted exactly that — *"needs no semantic change, only the field name"* — and the decisions log records the sentence as **struck, not softened**, with the other plan now stating the opposite and pointing at seam S1 as canonical. Two hazards the reconciliation found in `applyCost`, both closed in the shipped code:

- **The first-frame raw-store branch is gone.** Frame #1 used to early-return with the payload stored raw, which under the alias meant a legacy-shaped first frame produced an entry with no `costUsd` (renderer silent while money existed) and a D5-shaped first frame produced one with no `cost` (the card's alias link silent). Frame #1 now takes the identical normalise → combine → write-both-keys path with `prev = null`. The pre-existing test that asserted the raw shape via `toEqual` **reddened, was owned, and asserted the defect**, so it was rewritten as `normalises the first frame instead of storing it raw`.
- **One normalised value per frame**, so a mixed-key sequence cannot double-count: `{cost:0.005}` then `{costUsd:0.005}` is `0.01`, asserted with an explicit `not.toBeCloseTo(0.02)` (`a legacy frame and a costUsd frame SUM ONCE into one total, never twice`).

**The DOM.** A real `0` renders the literal `$0.00` (`moneyOf`'s rule 2 — D5 verbatim: a real zero IS a figure) and an unknown renders **no element** (`if (money === null) return null`), which is what makes the pane's "no phantom gap-child" assertion meaningful: the wrapper is the element that is or is not a child of the pane's `gap-4` column. The split between the two money helpers is deliberate and will read as duplication, so state it: `SessionCostLine` prints `$0.00` for a real zero, `formatCost` prints `""` — the session line distinguishes real-zero from unknown and the shared helper never did. **`formatCost`'s zero rule is untouched and must stay so**; `54ba649`'s message says *“the temptation to "clean up" the falsy return is the same collapse this commit exists to undo”* (attributed to the commit message — the shipped doc comment makes the same point in other words: returning `$0.00` there "is a different surface's rule").

**The sanitising rule, and the one filter it forbids.** Absent / non-numeric / negative / non-finite is **unknown** — never a clamp, never a panic; `0` **is** a figure. Written at four layers: `cost_usd_from_usage` (`Some(v) if v.is_finite() && v >= 0.0`), the subagent capture's parse (`.filter(|c| c.is_finite() && *c >= 0.0)`), `frameCost` in the store (*"A value that is not a finite non-negative number is UNKNOWN, not money: a string, `NaN`, `Infinity` and a negative all normalise to `null`. Nothing may invent a figure here."*), and `moneyOf`'s rule 1 at render time. The forbidden filter is **`!= 0.0`**, because it eats a legitimate real zero — which is why `-0.0` is handled by **`+ 0.0` sign-normalisation** at both Rust money seams instead. That normalisation is a real pin, not decoration: the implementer measured that ryu **does** print the sign, so `a_negative_zero_cost_emits_positive_zero` (asserting on the **serialised** string, because `-0.0 == 0.0` in both Rust and JS makes an equality check a tautology) has genuine discriminating power — attributed. And `a_child_that_reported_no_cost_reports_no_cost` deliberately keeps `-0.0` **out** of its negative cases, with the comment explaining that writing it there *"would push the guard toward a `!= 0.0` filter that eats a legitimate real zero"*.

**Two frame-existence gates are NOT instances of that rule, and conflating them is how the next wrong guard gets written.** `emit_cost_update`'s `let Some(cost) = cost else { return }` and `finish_subagent`'s `if rollup_cost > 0.0` decide **whether a frame exists**, not whether a value is money. The roll-up gate sits **on top of** the capture's sanitiser: a negative figure was already rejected upstream, so the gate never sees one, and its own shipped comment says what it is —

> The `> 0.0` guard is a FRAME-EXISTENCE gate, not a value filter: a child that reported nothing contributes nothing. It is deliberately not `!= 0` (which would eat a real zero) and it is NOT the loop's own emission path — the loop emits per call from the `Usage` arm with no such gate.

## The `$0.0000` cliff — the branch's defect class, arriving through a formatter

**The defect.** `formatCost` rendered **any positive value below `$0.00005`** as the literal `"$0.0000"` (`toFixed(4)` below `$0.01`). The measured per-call cost on the live proxy is **~`$0.0000117`** — T08's probes P1/P3 recorded `0.000011662`, `0.0000047597`, `0.00001243` and `2.122e-05` (T08's measurements, run once against one deployment, attributed and not re-run here). **Every real per-call figure in that deployment lands inside the band.** A fresh session displayed money being spent as free, for its first several calls.

**Why the obvious defence could not catch it.** `formatCost(v) || null` **cannot** catch it, because `"$0.0000"` is a **TRUTHY string**. Both consumers' gates passed for the same reason, and both files are worth naming because both have **zero diff** in all four commits: `SubagentDelegatingCard`'s chip gate is `row.cost !== undefined && row.cost > 0` then `if (formattedCost)` — `0.0000341 > 0` is true and the truthy string walks straight through `if`; `SubagentTranscript` builds its metrics segments and joins them with `.filter(Boolean)`, which **kept** it, so the line grew a ` · $0.0000` segment.

**How it reached two surfaces — the activation story, and the transferable half of this ADR.** The band was unreachable at both call sites for as long as `SubagentMetrics.cost` was a **hardcoded `0.0`** (`cost: 0.0` at two sites in `subagent_flow.rs` at `ada64f4`), because `formatCost(0)` is `""` and both surfaces suppress `""`. `405be65` replaced that `0.0` with the capture's real sum, so a four-call child arrived at ~`$0.0000341` and the dormant band became a live chip and a live transcript segment — **on two surfaces outside that commit's own diff, owned by neither of the two tasks that could see it.** A `SessionCostLine`-local rule could not reach either. `54ba649`'s message names it as *"REACHED BY A SIBLING TASK, NOT BY THIS ONE"*. It was fixed in a **separate commit on purpose**, as a shared-helper change granted to the frontend task — *"it must not be tangled into the feature commit or into the Rust task's diff"*.

**The lesson, in this ADR's own voice: a defect that is dormant because a field was hardcoded is not a defect that does not exist.** A test suite that is green because the input that would expose it was never reachable is measuring the **hardcoding**, not the helper. The corollary for the next task on this branch: **when you replace a constant with a real value, that value's magnitude is a new input to every consumer of the field, including consumers you do not own.**

**The seam, and why it sits where it sits.** `SUB_CLIFF_CEILING = 0.00005` is exactly where `toFixed(4)` stops rounding to zero — `0.000049999` used to print `$0.0000` and `0.00005` printed `$0.0001` and still does — which makes the local rule **byte-identical to `formatCost` across `[0.00005, ∞)`** (measured by the implementers: 0 mismatches over 20 000 samples in `[0.00005, 0.01)` and 0 in `[0.001, 20]`) and different from it **only strictly below the cliff, where the helper was wrong.** A `0.0001` seam would have created a band in which two surfaces print two strings for the same money. Below the ceiling a figure gets two significant digits (`$0.000034`); below `1e-6` the session line prints the truthful inequality `<$0.000001` while the shared helper prints the exponential `$9.9e-7` — **a chosen residue, with the shipped reason**: *"inventing a second rule for a band nothing produces is how the next rounding lie gets written."*

**The rejected alternative, named because someone will re-propose it:** documenting the subagent chip as "rounded to four decimals". `54ba649`'s message records the refusal — *"That writes down a lie to avoid a patch"* — which is attributed to the **commit message**; the shipped doc comment carries the same reasoning in its own words and never uses that phrase. Guards now in the tree: `never renders a real non-zero sub-cliff figure as $0.0000`, `is byte-identical to its old output at and above the sub-cliff ceiling`, and `matches formatCost exactly wherever formatCost is truthful (no split-brain between surfaces)`.

**Correct the number the branch has been repeating.** A grant note cited **"499 output changes"** as the blast radius. `54ba649`'s message records that figure as **sampling-grid dependent** — 500 on a `1e-7` grid, 50 on `1e-6`, 470 on a log sweep — and *"should not be quoted as a fact"*. This ADR does not quote it. The **load-bearing half reproduces exactly**: every output change falls strictly below the seam, and every value any existing test seeds is byte-identical (`0 → ""`, `0.0042`, `0.15`, `0.035 → $0.04`, `0.02`), with `toolOutput`, `SubagentTranscript` and `SubagentDelegatingCard` green unmodified. This is precisely the kind of number a later document would otherwise launder into a measurement by copying it.

## The subagent roll-up is NEW, not "the existing path"

The roadmap's D4 path line said subagent cost *"rolls up through the existing `SubagentMetrics` path"*. That was **false**, and three shipped facts prove it: a child's frames reach `observe_sink_frame`, which early-returned on anything but `session-update`, so the money hit the floor; `SubagentMetrics.cost` was a hardcoded `0.0` at both sites, so every child reported as free; and `dispatch.rs` discards the metrics — `let _ = (reason, metrics);`, with the comment *"The `reason` and the child's REAL usage are NOT part of the parent's prompt"* — so a parent-loop total **structurally cannot** include children. The roll-up therefore had to be **Supervisor-side**, and `finish_subagent`'s shipped comment says exactly that.

What ships: `SubagentCapture` gains a `cost: StdMutex<Option<f64>>` with an `interactive-event` branch placed **before** the `session-update` early return, scoped to the one event name (`observe_sink_frame_still_ignores_unrelated_interactive_frames` — the `todos_update` push rides the same channel). It is a **sum**, and the comment refuses the neighbouring rule: *"A SUM, deliberately NOT a `max` like the token fields next door: … money accumulates across calls — copying the `max` rule here would report one call's cost for a ten-call child"* (`a_child_cost_frame_accumulates_across_calls` is the pin that discriminates the two). Both `cost: 0.0` sites read `capture.cost_usd().unwrap_or(0.0)`, including the failure/salvage path — *"a child that died after four priced calls spent real money, and the salvage exists precisely so its work is not reported as free"* (`a_failed_childs_cost_still_rolls_up`). Then `finish_subagent` emits **one** parent-keyed frame directly on the parent's sink with `"source": "subagent"`, behind the `> 0.0` frame-existence gate. No double count, and the reason is a key split: the child's own frames carry the **child** id, the roll-up carries the **parent** id, so they land in different store keys (`the_rollup_frame_is_keyed_to_the_parent_not_the_child`); and the emission goes to the parent's Tauri sink directly, so it never passes the router's persistence arm.

**The `Option` is preserved right up to the hand-off and collapsed at it, and that collapse is documented, not fixed.** `SubagentMetrics.cost` stays an `f64` and the shipped doc comment states what `0.0` means there:

> **What `cost == 0.0` means here:** no call reported a cost, OR a call reported a real zero. Those two states are genuinely different and this field cannot tell them apart — the capture holds `Option<f64>` right up to the hand-off, and the collapse happens at `unwrap_or(0.0)`. Promoting this to `Option<f64>` requires moving the TypeScript `metrics` declaration (`src/lib/tauri/types.ts`) and the card's read in the SAME change, so the field stays `f64` and the collapse is documented rather than hidden. Both consumers render nothing for a zero, so a `0.0` never displays as a figure.

The wire shape is unchanged and pinned (`metrics_json_keeps_the_wire_shape_exact` — the key set is exactly `{output, inputTokens, outputTokens, cost, durationMs}`), because the card and the transcript read it today and no frontend file is owned by the Rust task.

## Honest limits — six, stated as shipped

A future reader must not be able to take this ADR as evidence that #87's figure is verified against the provider's ledger. All six limits, with their follow-up pointers:

**1. The figure does not survive a reload.** No cost column in `storage/db.rs` (re-measured: `grep -ci cost src-tauri/src/storage/db.rs` → **0**, armed by the same command over `harness/catalog.rs` → 7), no `costUsd` on `SessionInfo` (`src/lib/tauri/types.ts` carries `contextUsage` and no money), and no hydrator into `useInteractive.cost` — `applyCost` is its only writer. Follow-up **F1**, recorded as a **pinned defect, not accepted behaviour**. The rule attached to it is *"Until it lands, the shipped copy must say the figure is per-live-session"* — recorded from `4b802b9`'s message and T09's F1, and **measured honestly: no string in `src/` says "per-live-session"**, so the requirement is met so far only in the negative — nothing in the shipped UI or the store claims persistence, `SessionCostLine`'s comment says *“"Cumulative" means the sum of the frames the provider sent, so the copy must never be re-labelled "what this session cost"”*, and `useInteractive.cost`'s doc comment names `applyCost` and **frames** as its only writer and route. That is the copy not lying; it is not yet the copy stating the limit, and F1's implementer or the feature-doc task should say it out loud. **The rule F1 must obey, because it is a trap, not a detail:** a stored **total** must write the store key **directly** (the way `src/store/sessions.ts` copies `contextUsage` off the DB row) and must **never** route through `applyCost` — which now normalises *and sums*, so feeding it a stored total re-adds it to itself.

**2. It is not "total spend."** The summariser's own call is **uncosted**: `compact.rs`'s summarise loop matches `TextDelta` / `Done` / `Error` and its `_ => {}` arm swallows `ProviderEvent::Usage`, so the figure under-states by one summariser call per compaction. Follow-up **F2**, excluded from #87 by design. The magnitude in the plans' own words: *unbounded in the abstract, zero on a deployment that prices nothing.* This is why `SessionCostLine`'s copy says "as the provider reported it" and must never be re-labelled "what this session cost".

**3. The subagent roll-up is ONE level, and a real-zero child contributes nothing.** A grandchild's money stops at its own parent — `finish_subagent` knows only its immediate parent (follow-up **F4**, accepted). And because the roll-up gate is `> 0.0`, a child whose calls all reported a genuine `0` adds **no frame** to the parent: an accepted, stated collapse, sitting on top of the `f64` hand-off (follow-up **F3**). D5's real-zero state therefore cannot arrive by the roll-up path at all.

**4. The ledger arithmetic is FIELD-PATH-CONFIRMED, LEDGER-NOT-CONFIRMED, and must never be recorded as verified.** The proxy's spend endpoints were unreachable (`/spend/logs` timed out; `/spend/transactions` and `/spend/summary` 404), and `/key/info`'s `spend` is a **shared** key total whose idle drift (~`0.0000476688` per 25 s with no call at all) **exceeds a single call's cost** (~`0.00001377`), making attribution impossible on that key. **BLOCKED-PENDING-HUMAN** — it needs a dedicated key or operator log access. This is the ADR applying its own thesis: the field path is what was observed; agreement with the bill was not, so this document does not claim it.

**5. The figure is only as honest as the gateway.** `usage.cost` **under-reports on Claude web-search streams** (LiteLLM rebuilds the usage dict from five fields and drops search fees), and `include_cost_in_streaming_usage` is an **operator-side flag the client cannot enable**, default **off** — so most deployments will show **no figure at all**, which is the accepted, documented reason absence is the ordinary case rather than a bug. Both are `accepted` in the follow-ups inventory; the second carries a **documentation obligation that is still unmet** — re-measured: `grep -rln "include_cost_in_streaming_usage" docs/features/` prints **nothing**, while the identical pattern over `docs/roadmap/` finds it in five files — so the pattern can hit and the `docs/features/` emptiness is a real gap, not a vacuous sweep. Absence is per-**call**, not per-deployment: on the same cooperative proxy, cache-served calls carried no `cost` at all (probe P6), so a session reporting money on 3 of 10 calls is normal.

**6. Two of the three wires' cost paths are pinned by canned JSON only.** `usage.estimated_cost` (DeepInfra) has never been observed on a reachable wire, and the **Anthropic Messages wire returned no money at all** on the live proxy (probe P4), so its cost reading is a deliberate superset of plausible injection points rather than a live-verified path. This ADR does not let three wires read as three verified wires.

**Plus the residue the plans recorded and this ADR carries: the openai-shaped parsers have no exactly-once guard.** Anthropic has `usage_emitted`; `SseStream` and `ResponsesStream` rely on the wire shape. `emit_cost_update` therefore adds **no dedupe of its own** — a per-call identity the loop does not have — so a deployment that repeated `usage` on every chunk would make the store **over-count**. This is **observed, not guaranteed**: probe P1 saw the money on the **final** chunk only, and no loop-side test can see it because `ScriptedProvider` injects events past the parsers. If it ever bites, the fix belongs at the **parser** seam, not in an accumulator.

## What refutes this

Two observing conditions, each with the change it forces. Stated **live**, not discharged.

**A provider is observed reporting a cost that disagrees with what we display** — a session whose summed frames disagree with the gateway's own per-call figure, or with its ledger. Then the seam is wrong, and specifically one of **three named candidates**, which is what makes this falsifier actionable rather than rhetorical:

- the **field order** — we read a gateway's figure where the upstream's was the billed one (mitigated but not eliminated: the order is pinned only by a differing fixture, `cost_usd_from_usage_prefers_the_gateway_cost_over_the_upstream_detail` at `0.002` / `0.009` / `0.007`, because on the live gateway the primary and the upstream detail are numerically **identical** — probe P3);
- the **exactly-once assumption** — a parser emitting more than one `Usage` per call, so the store over-counts (remedy: a once-guard at the **parser** seam, as Honest limits' residue names; **not** an accumulator);
- **Anthropic's last-non-`None`-wins** rule — a later usage object superseding a figure it should not have.

The remedy is explicitly **not** "re-derive the price": re-deriving is the rejected design, and a falsifier whose remedy walks back the decision should say so.

**A session is shown as free while spend is confirmed** — a `$0.00`, a `$0.0000`, or no line at all, on a session the operator's bill says cost money. Then the unknown≠zero machinery has a hole at whichever layer produced it, and **this ADR is superseded for that layer**: the wire (a frame emitted for a `None`), the store (a `null` collapsed to `0`), or the formatter (a rounding lie re-appearing). Per-layer supersession is the honest form here precisely because the three layers were fixed in three separate commits and can break separately — the `$0.0000` section is the proof that one of them already did.

**Live, not discharged** (0079's and 0080's standard): nothing in this tree observes real sessions **or** the provider's ledger, and the one instrument that could test the main falsifier is BLOCKED-PENDING-HUMAN. "No disagreement has been seen" is not a claim anyone here is entitled to upgrade into "none exists" — it is a claim the only available instrument cannot even ask.

## Considered Options

- **A static price table on `Model.cost_per_mtok_*`** (the superseded on-disk plan's central decision): rejected — **22 initializer pairs, two declarations, zero reads**, `ModelDto` does not project them, and 0076 already records them as never read; a price table **invents** a figure rather than observing one, and it would need a cache discount it cannot compute because 0046 deliberately collapses the cache split. The fields stay in place; deleting them is separate cleanup.
- **The `x-litellm-response-cost` header** (and the `-input` / `-output` / `-cache-read` component headers): rejected — headers commit before the stream ends and **this app always streams**; the component headers are non-streaming-only, forcing either a partial figure or a second mechanism. LiteLLM #30816 / #46364 / #12689 / #26475, plus its pass-through contract page conceding the limit. Independently confirmed on the live proxy: probe P5 found the header **absent from every streamed response captured**.
- **`Option<f64>` on the `Usage` STRUCT**: rejected — it drops `Eq` and reaches all 11 `compact.rs` anchor pins, dragging money into compaction accounting to move a display figure.
- **Adding `|| self.cost_usd.is_some()` to `emit_usage`'s guard**: rejected — it emits `Usage(0, 0, Some(money))` and `record_usage` writes a **ZERO Anchor**: a compaction regression bought for a figure. A cost with no counts is dropped, on every wire, by design.
- **A running total from Rust** (an `AgentLoop` field, or emitting totals): rejected — the accumulator is per **model call**, so a per-turn total is wrong by construction; and a totals contract into a summing store resets on `Resume`/re-incarnation and double-counts when it does not.
- **`costUsd: null` on the wire for an unknown figure**: rejected — the phantom zero is prevented by **not emitting**; a `null` on the bus would make "we did not look" and "it was free" two spellings of one number, and the store is where the distinction belongs.
- **Keeping `?? 0` in `applyCost` and only renaming the key**: rejected — that is the phantom `$0.00` with a new label, and it is what one plan asserted was fine before the sentence was **struck**.
- **Routing the session figure through `formatCost`**: rejected twice over — `formatCost(0)` is `""` (killing D5's `$0.00` row) **and** it rendered every real per-call magnitude as `$0.0000`. Hence the local rule; hence the separate helper fix.
- **Documenting the subagent chip as "rounded to four decimals"**: rejected — it writes down a lie to avoid a patch.
- **`!= 0.0` filters to keep signed zeros off the wire**: rejected — they eat a legitimate real zero. `+ 0.0` normalises the sign without touching the value's meaning.
- **`if rollup_cost != 0.0` (or no gate) for the subagent roll-up**: rejected — no gate lands `cost[parent] = 0` and renders `$0.00` for a child that reported nothing (`a_child_that_spent_nothing_emits_no_rollup_frame`); `!= 0` would eat a real zero. `> 0.0` is a frame-existence gate.
- **Supersede an ADR / set `superseded-by`**: rejected — nothing in `docs/decisions/` governs cost reporting (measured, three cost-adjacent hits, none applicable); 0046 is **depended on**, 0026 and 0076 are **re-affirmed**.

## Consequences

- **`Option` is the design, not a detail.** It appears at the event, at the capture, at the store entry and at `moneyOf`'s `null`, and every one of them exists so that "the provider said nothing" survives all the way to the DOM. **Any future consumer that writes `unwrap_or(0.0)` on this path re-creates #87.** The one place that already does is named and bounded: `SubagentMetrics.cost` (`unwrap_or(0.0)`, both consumers render nothing for a zero, follow-up F3). Nothing else on the money path collapses an `Option`.
- **Adding a fourth cost field means re-deciding the reader's order.** `cost_usd_from_usage` answers with the **first present** field and treats a present-but-unusable field as a `None` verdict, **not** a licence to fall through to another field's figure (*"a malformed `cost` is `None`, not a licence to fall through to a different field's figure (which would report a number the primary did not carry)"*). A new provider field is a design change, not an array edit. The differing-values fixture is what makes the order falsifiable, because on the live gateway the primary and the upstream detail are numerically identical.
- **`is_finite()` is defence-in-depth and cannot be pinned at the reader — recorded rather than hidden.** The shipped doc comment's own reasoning: with `arbitrary_precision` off (the feature set it names, and `Cargo.toml` pins plain `serde_json = "1"`), `as_f64()`'s non-arbitrary arm is a bare `Some(n)`, so `>= 0.0` alone would let an `inf` through; but a non-finite literal never reaches the reader at all, because serde_json rejects the **whole chunk** with `number out of range`. `ada64f4` records that deleting `is_finite()` reddens **nothing**, so the tempting reader-level "non-finite → None" pin is a **tautology and was not written**; the honest claim lives on the wire instead (`sse_usage_chunk_with_an_unparsable_number_emits_no_usage_event`, which also proves the failure is scoped to the one bad line). 0079 sets this standard by recording a vacuous assertion rather than hiding it.
- **`cost_update` is now a live channel with one emitter and two renderers.** 0046's "only `todos_update` is pushed" is stale (see the Amendment row); `events.rs` still has no variant and **must not gain one** — a frame is an `interactive-event`, and `a_cost_frame_is_not_an_rpc_event` proves it by grepping the serialised wire.
- **A hydration path must bypass `applyCost`.** Stated once, where the store says it: `cost[sessionId]` is written only by `applyCost`, from **frames**; a hydrator holding a stored total writes the key directly.
- **The `cost` / `costUsd` alias has two roles and two expiries,** and the card's own shape is an `as` assertion, so **`tsc` will not protect the alias** — its safety is the card's runtime `> 0` gate, which `null` fails. Both halves expire in one change (repoint the card, drop the input fallback, drop the field, clean the legacy seeds), and that change is **sequential and lands strictly after this wave** (seam S4).
- **A cost frame must never be routed into `record_usage`.** The guard is `a_cost_frame_leaves_the_context_usage_anchor_alone`, and the reason is the ZERO Anchor — the same argument the parser-side guard carries, from the other end of the pipe.
- **The cross-task contract lesson (briefly, because an ADR records a decision's shape and not a project's process).** Two tasks each advertised a "shared contract" table of **five** points whose content agreed on every fact — but the same row number meant a different fact on each side, so the **union was seven facts and only three were numbered on both sides**. The decisions log carries the durable wording: *“A faithful implementer told to "re-diff the contract table" would have reported phantom drift, and a real divergence could hide in the gap between the two numberings.”* The rule: **a contract shared between tasks must be enumerated identically in both documents, or checked per-fact and reported per-fact.** What actually worked was the **seam table** (S1 `applyCost` semantics → T10; S2 the payload field set → stated verbatim in both; S3a the local money rule → T10; S3b the shared-helper cliff → **T09, because T09's own roll-up activated it**; S4 the card repoint → both, verbatim), because it gave every disagreement **one canonical home**. **S3b is the one to single out: the seam that mattered was found by the task that *caused* it and fixed by the task that *owned the file*** — the pairing a shared contract needs, and it only happened because the seam table forced each disagreement to have exactly one home.

## Amendment (2026-10-27) — the ledger arithmetic was reconciled by the operator; limit 4 is discharged, the other five are not

**AMENDED 2026-10-27 — one of the six honest limits has been closed by observation, and the paragraph that forbade recording it as verified is now overtaken by fact.** What stands unchanged, and stands *harder* for being tested: the seam (cost rides the `Usage` **event**, never the `Usage` struct), **deltas not totals**, unknown-is-not-zero at all three layers, the `$0.0000` cliff and its activation lesson, the subagent roll-up's one level, and the rejection of both the static price table and the response header. This ADR is NOT superseded and its `status` is unchanged. **Limit 4 above is deliberately left standing exactly as written**, including its `BLOCKED-PENDING-HUMAN` verdict and its instruction that the arithmetic "must never be recorded as verified" — that is a true record of what was knowable on the day it was written, and correcting it *in place* would erase the reasoning that made the check worth doing. The correction is here, below.

**What changed.** The operator — the one person with access to a LiteLLM proxy that has `include_cost_in_streaming_usage` enabled, which is the flag this ADR's limit 5 says is off by default and unreachable from the client — ran a real session, watched the figure increment across calls, and compared the summed total against the proxy's own ledger. **They agreed.** What closed is the item this ADR itself named `BLOCKED-PENDING-HUMAN`, filed as issue #111 and closed on 2026-10-27. So the sentence *"agreement with the bill was not [observed], so this document does not claim it"* is now false, and this amendment is what claims it.

**The attribution is the load-bearing half of this amendment, so state it exactly.** The check was performed by **a human looking at two numbers**, not by any instrument in this tree. Limit 4's underlying reason for refusing the claim was structural and it has **not** changed: the proxy's spend endpoints remain unreachable from here (`/spend/logs` timed out; `/spend/transactions` and `/spend/summary` 404), and `/key/info`'s `spend` is still a shared-key total whose idle drift (~`0.0000476688` per 25 s) exceeds a single call's cost (~`0.00001377`). Nothing testable was built. **The tree still cannot ask this question** — "Live, not discharged" remains the correct description of *the repository's* instruments, and remains true of them after this amendment. What changed is only that a person who *could* ask it, asked it once. A future reader must therefore record the state as **field-path-confirmed and ledger-confirmed-once-by-operator**, never as "verified", and never as reproducible: a second run of that check needs the same operator and the same proxy, and no CI leg anywhere can substitute for it. That is the same discipline this ADR applies to every other measurement — the mutation results are attributed to T06's implementer rather than restated as independently re-verified, and this is attributed the same way.

**An incidental downgrade, weak but worth recording because it lands on the primary path.** Both unguarded variants are live on this deployment: of its 11 LiteLLM models, **8 are `api=openai-completions` and 3 are `api=openai-responses`** (re-measured from the model store — an earlier draft of this amendment said "all 11" were `openai-completions`, which is wrong, and the correction matters because the truth is the stronger claim). Both of those are exactly the pair the residue above flags as having **no exactly-once guard** (Anthropic has `usage_emitted`; `SseStream` and `ResponsesStream` have nothing), and both are named in issue #108. A repeated `usage` chunk would have made the store over-count, and the app would have read **high** against the ledger. It did not, across a multi-call session. So the exactly-once assumption **held under real traffic on the unguarded parsers** — for whichever of the two variants that session actually drove, which the operator did not record, so this amendment does not claim coverage of both. That is one session of evidence, not a guard: it does not close the residue, issue #108 stays open, and the remedy remains a once-guard at the **parser** seam rather than an accumulator. But it moves the risk from "latent, may bite the primary path" to "latent, did not bite a real session", and a future triage should read it as the latter.

**What this discharges, precisely:** limit 4, and with it the falsifier's *ledger* half — "a session whose summed frames disagree with its ledger" has now been asked and answered once, in the negative. **What it does not touch:** limits 1 (no reload survival — #105), 2 (the summariser's own call is uncosted, so this is still not total spend — #106), 3 (one-level roll-up, real-zero child contributes nothing), 5 (the operator-side flag, and the **still-unmet** documentation obligation — `docs/features/` says nothing about it, so most deployments will still read absence as a bug), and 6 (the Anthropic wire was observed reporting **no money at all**, and `usage.cost_details.upstream_inference_cost` / `usage.cost_details.estimated_cost` have still never been seen on a reachable wire). The falsifier's other two candidate seams — the **field order** (pinned only by a differing fixture, because on the live gateway the primary and upstream figures are numerically identical) and **Anthropic's last-non-`None`-wins** rule — are untouched by a check that ran on `openai-completions` and cannot speak to either.

**Re-armed, because a discharged falsifier that cannot be re-run is decoration.** The condition that would reopen this is now narrower and sharper than limit 4's original wording: a session on **this** deployment whose summed frames disagree with the ledger, or **any** figure appearing on a wire where none was seen before (Anthropic, or a `cost_details`-only gateway). And because the check is human, it must be **re-run when the seam moves** — a change to the field order, to a parser's emission guard, or to `applyCost`'s summing invalidates the 2026-10-27 reconciliation for the path it touched, exactly as re-deriving the price would have invalidated the whole design. That is the cost of a human-verified claim: it does not self-maintain.

**Left deliberately alone outside this file.** `CONTEXT.md`'s **Session cost** entry still names the rejected `x-litellm-response-cost` header in a parenthetical while getting every other clause right, including its `_Avoid_` list; that one-parenthetical fix is issue #110, not this amendment, for the reason already given in this ADR — the ADR tasks did not edit the glossary so that four documents would not each rewrite it.

## Amendment (2026-10-27, second) — limit 1 is closed by #105; the accumulator moved seam, and the decision above stands

**AMENDED 2026-10-27 — limit 1 has been closed by implementation, and the sentence that stated it is now false.** What stands unchanged: the seam (cost rides the `Usage` **event**, never the `Usage` struct), **deltas not totals**, unknown-is-not-zero, the `$0.0000` cliff and its activation lesson, the one-level roll-up, and the rejection of both the static price table and the response header. This ADR is NOT superseded and its `status` is unchanged. **Limit 1 is deliberately left standing exactly as written**, including its now-retired instruction that the shipped copy must say *per-live-session* — that is a true record of what was true when it was written, and the correction belongs below, in the idiom this file already uses for 0016 and 0046.

**What shipped.** Issue #105, PR #114, merged 2026-10-27. `sessions.cost_usd` — a nullable `REAL`, `ALTER TABLE … ADD COLUMN cost_usd REAL` with **no `DEFAULT`** — accumulates the same per-call deltas the frontend has always summed. `SessionInfo.costUsd` projects it, the renderer prefers the live store entry when one *exists* and falls back to the row otherwise, and a resumed session is seeded from the row. The figure now survives a reload **and** an in-run close; the close needed its own fix, because the store dismissed the entry while the row copy filed into history still carried the session's start-time figure.

**The decision at the head of this ADR is not reversed, and reading it as reversed would be the easy mistake.** *"Rust holds no accumulator"* is about the **Worker**, and it remains exactly true there: `emit_cost_update` still emits one frame per call carrying that call's delta and nothing else, `AgentLoop` still holds no running total, and it still has exactly one production call site (`turn.rs`, the `Usage` arm). What changed is the accumulator's **location**, not its grain — the sum now lives in the **Supervisor**, which is the sole DB writer because the Worker holds no `Db`. The reason this ADR gives for refusing a loop-side accumulator is the reason the fix could not go there either: a re-incarnation or `Resume` rebuilds the loop with no memory of the old figure. Putting the total somewhere that outlives the loop is precisely what that argument asks for.

**Unknown-is-not-zero now holds at a fourth layer.** This ADR required the distinction at the parser, in the store, and in the renderer. It holds at rest too: a `NULL` column means no call ever reported a cost and a stored `0.0` means a call reported a genuine zero, pinned by `a_null_cost_and_a_real_zero_are_different` and by a serde-boundary test asserting `None` and `Some(0.0)` serialise to **different payloads**. The trap this ADR named for the fix — *a stored total must write the store key directly, never through `applyCost`, which normalises and sums and would re-add the total to itself* — is obeyed, and the pins that actually bite are the no-second-accumulation and no-clobber cases; the arithmetic case alone does not distinguish a direct write from a sum into an empty map, and its own test comment says so.

**Closing limit 1 opened a new one, so "six, stated as shipped" is no longer the count.** **The persisted write is not idempotent, and cannot be made so at this seam:** `cost_update` frames carry no identity — `emit_cost_update` hardcodes `"seq": 0` — so a re-delivered frame doubles the stored figure. Bounded by the emitter's single call site (a `Resume` cannot re-emit history) and **pinned rather than prevented**: `a_replayed_cost_frame_doubles_the_stored_figure` asserts the doubling and states that a change making it idempotent must delete the test, not soften it. `persist.rs`'s module doc names `cost_update` as the one arm where its idempotency promise does not hold. A future reader should treat this as limit 7, not as a defect that escaped notice.

**The amendment immediately above is overtaken on one clause, and only one.** Its heading says *"limit 4 is discharged, the other five are not"* and its closing list names limit 1 as untouched — *"(no reload survival — #105)"* — which was accurate on the day it was written and is not now. Its ledger finding, its attribution discipline, its exactly-once downgrade and its re-armed falsifier are all untouched by this second amendment; only that enumeration moves. Read the two together, in this order.

**What this discharges: nothing else, and no falsifier.** Reload survival was never one of the three observing seams — field order, the exactly-once assumption, and Anthropic's last-non-`None`-wins are — so **"What refutes this" is untouched and stays live**, and the ledger amendment immediately above still governs limit 4. Limits 2 (the summariser's own call uncosted, `compact.rs`'s catch-all still drops `Usage` — #106), 3 (one-level roll-up; a real-zero child still contributes no frame), 5 (the operator-side flag, and its still-unmet documentation obligation — #109), and 6 (two of three wires pinned by canned JSON only) all stand, as does the residue: `usage_emitted` is still confined to the Anthropic parser and #108 stays open. Two deliberate non-goals belong here too: **no token fields are persisted** — the frame never carried them, so `applyCost`'s token accumulation is provably `0 + 0` in production and widening the frame would activate `SubagentDelegatingCard`'s never-executed context-percentage path, unclamped and fed by a summed field whose values are cumulative per call; and the roll-up's end-to-end proof stops at the seam where `fake_worker` reports no cost, which the test asserts before injecting the envelope rather than papering over.
