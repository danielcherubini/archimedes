# Session naming runs in the Supervisor, and `WHERE title IS NULL` is the entire write contract

`@pi-archimedes/session-name` asks a model for a 3–8 word title once a session's first exchange settles, and writes it as the session's name. Ported to the desktop, that is a model call plus a write to a row — and ADR 0025 makes each half belong to a different process: the **Worker** owns the conversation, the **Supervisor** owns the `sessions` row and every UI frame. We decided: naming is a **Supervisor** concern end to end. The hook is the existing `SessionManager::route_event` bookkeeping arm for `WorkerInboundEvent::Event` (`agent/session/router.rs`), which is the exact analog of pi's `agent_end` handler; on a MAIN session's `agent_end` it calls `SessionManager::maybe_name_session` (`agent/session/naming.rs`), which runs the guard ladder synchronously and then `tokio::spawn`s one detached task holding owned clones (`Db`, `EventSink`, `ProviderFactory`, `EffectiveCatalog`, the resolved `Model`, one `Settings` snapshot). That task reads the first exchange out of `native_messages`, makes one no-tools request, and lands the answer with `UPDATE sessions SET title = ?2 WHERE id = ?1 AND title IS NULL` (`Db::set_session_title`), emitting `session-titled` only when that statement actually wrote a row. The invariant: **a session is named at most once, by the Supervisor, and only while it has no title** — the SQL predicate, not any Rust-side check, is what makes that true.

**Why:** the Supervisor already holds every input the request needs and the Worker holds none of the outputs it produces. Naming needs the transcript (`SessionStore::load_messages` on the shared SQLite handle — ADR 0025 made `native_messages` Supervisor-readable), the live session's resolved `Model` (`config_state`, which is what carries `api_key` and `thinking_levels`), the catalog for an override model, the `Db` to write into, and the `EventSink` to push the label — all Supervisor state, and none of it reachable from a Worker without a new IPC variant for the write plus a second one for the label. The hook site is not new machinery either: `route_event` already matches `RpcEvent::agent_settled` to resolve the in-flight turn, so `agent_end` costs one `matches!` beside it, and the owned-input background task is the same shape `subagent.rs::dispatch_native` already uses — no `Arc<Self>` back-pointer, no cycle, nothing for the task to keep a dead session alive. And because `agent_end` fires on EVERY turn, the guards have to be the ones that make it fire at most once, which is exactly what the conditional write gives us for free: the guard ladder (settings off → no `Db` → row missing / already titled / `is_subagent` → `fails >= 3` or in flight → no resolved `Model` → no user text) declines a repeat, and the `UPDATE` catches the race no Rust-side read can close.

**Considered Options**

- **Worker-side naming + a `session_title` store frame**: rejected — the Worker would need to write a Supervisor-owned row, so the change grows an IPC variant, a persistence arm, and a second copy of the model-auth and catalog resolution, to move a write that is one statement long.
- **An `Arc<Self>` back-pointer on `SessionManager`** (the task borrows the manager): rejected — the owned-input shape needs no back-pointer, and a `'static` task holding `Arc<SessionManager>` outlives `close_session`, which is precisely the state we then have to tear down.
- **A Rust-side read-then-write** (`if row.title.is_none() { write }`): rejected — pi needs that shape (its `sessionManager.getTitle()` read is asynchronous, so it re-checks after the await); here both the read and the write take the same `Db` mutex, so the two-statement version is strictly weaker than the one-statement version. The pre-read stays only as a cheap decline that avoids building a prompt for an already-named session.
- **Pi's `minimal` reasoning default**: rejected — pi asks for `minimal` because a pi call carries thinking unless told otherwise, while `ModelOptions.reasoning_effort: None` already means "no thinking" on every adapter here, so porting the default would ADD cost to a request whose whole job is to be cheap.
- **Pi's fixed reasoning vocabulary** (`minimal…xhigh`, `off` excluded): rejected — the desktop's models advertise levels per-model (`Model.thinking_levels`) and several providers spell "no thinking" `off` / `none`; validating against a fixed list would either reject a level the model understands or forward one it does not. `ModelOptions.reasoning_effort` is forwarded verbatim by every adapter, so an unverifiable level is provider-dependent: some read an unknown value as MORE thinking, some reject the request.
- **Naming from the Client** (the frontend calls a `generate_title` command): rejected — the Client has no transcript access and no `Model`, so it would need both shipped to it, and the write would still be a Supervisor command; it also delays the title by a round-trip per turn for a one-shot decision.
- **Tie the request to the turn's cancel token**: rejected — the title is still wanted after the turn settles (and after the next prompt starts), and cancellation would need a new handle on a task deliberately detached from the turn. The row-level guards already make an irrelevant in-flight request harmless: it either writes `NULL → title` (still correct) or loses the predicate and writes nothing.
- **A rename affordance in the same change**: rejected — no `title` setter command, no `session_renamed` event, no UI. It is the natural follow-up and it does not need to be designed under the pressure of this port; `#[serde(default)] title` plus a nullable column already carry whatever a rename needs to add later.

**Consequences**

- **The `title IS NULL` predicate is now load-bearing for every future writer.** `record_session`'s `ON CONFLICT DO UPDATE` set-list deliberately EXCLUDES `title`, so a resume cannot clobber a stored name, and any future rename command must decide deliberately whether to keep or replace that predicate. Because nothing else writes `title` today, `Some(title)` means exactly one thing: the naming pass wrote it.
- **A bad title is permanent.** A titled session is never re-titled and there is no rename UI, so a wrong or unhelpful title survives every later turn and every restart. The user's levers are: turn "Name sessions automatically" off before the first exchange, or delete the session. Accepted as the cost of shipping auto-only.
- **The assistant side of the excerpt may not be durable yet when the hook reads it.** The `RpcEvent` stream and the store frames ride different outbound paths (`worker/core.rs` pumps `Outbound::Event` separately from the `TranscriptInsert` frames), so `agent_end` can arrive before the assistant row is applied. The result is a title written from the `User:` line alone — acceptable because the assistant side is optional by design (pi's `conversationText` is non-empty on the user line alone), and it is never revisited because the write is once-only. NO retry, sleep, or re-read loop was added for it.
- **A compaction can summarise the first exchange away.** `run_compaction` → `replace_native_messages` rewrites the excerpt's source. Naming completes on the first turn in practice; if the first user row is already summarised, the title comes from whatever survives. No special handling.
- **Subagent sessions are never named** — guard on `is_subagent`, tested at both layers: the frame level (`route_event` is called with `is_subagent: true`) and the row level (an `is_subagent` row declines). A subagent's transcript is hidden from `list_sessions`, so naming one would write a label nothing renders.
- **Per-session bookkeeping is torn down on BOTH exit paths, and a late failure cannot resurrect it.** `on_session_exited_expected` (the ONE clean-exit / `close_session` teardown, beside the `config_state` removal) and `handle_crash` (the unexpected `Exited`, which tears down the modals but not the per-session maps — a pre-existing `config_state` leak, deliberately unfixed here) both remove the `naming` entry: a crashed-then-resumed session re-uses the SAME id, so a stale `in_flight` would block naming forever and a stale `fails == 3` would silently kill it. `note_failure` uses `get_mut`, never `entry().or_default()`, so a request that fails AFTER the teardown finds no entry and creates none; `InFlightClaim`'s `Drop` clears the flag on every early return.
- **The title request is attributed to its session in LiteLLM, deliberately NOT pi-style.** pi issues the call under a fresh `crypto.randomUUID()`; here `ModelRequest.session_id` carries the REAL session id, so `transport::litellm_headers` stamps `x-litellm-session-id` / `x-request-id` on it like any other request of the session (the attribution ADR 0026 records the harness already sends). So the title request's tokens are visible in the LiteLLM dashboard and nowhere in the desktop: the task emits exactly ONE event (`session-titled`), produces no store frame and no transcript row, and runs outside any **Agent harness** loop, so no per-turn usage of it reaches the Client — its cost is LiteLLM's to show, not the desktop's.
- **Failures are silent by design, and the 3-failure budget is a log line.** An empty `api_key` declines WITHOUT counting a failure (pi: unconfigured auth is not a naming bug); a provider error, a timeout (30 s, stream drain only), a `Done(Error)` / `Done(Length)` finish, a stream with no finish, and an answer that cleans to nothing each count ONE failure, and the third logs `session-name: naming failed 3 times for <id>; check the model configuration or set sessionNamingModel`. The desktop has no toast primitive, so the warning is an `eprintln!` in the crate's existing convention (`agent/persist.rs`, `config.rs`) — the deliberate gap this ADR states rather than closes: a user with a misconfigured naming model sees only that naming silently stopped.
- **`sessionNamingEnabled` defaults to TRUE**, so a pre-feature `settings.json` starts naming on next launch (`#[serde(default = "default_true")]`), unlike this crate's other new bools whose default is `false`. `sessionNamingModel` accepts `provider/id`, a tolerated `:level` suffix, and a bare id unique across providers — case-insensitively, deliberately NOT via `resolve_composed_model`, which compares with `==` and would silently miss a hand-edited `TAMA/m1`. `sessionNamingReasoning` is JSON-only: a thinking-level row for a request that should cost nothing is not worth a third picker.
- **Excerpt and title are capped in CHARS, never bytes.** 500 chars per side, 80 chars for the title, both by `.chars().take(n)`: pi's JS `.slice()` is char-based too, and a byte slice would panic mid-title on the emoji and CJK text that a real first message contains. One layer of matching surrounding quotes is stripped with pi's exact regex semantics (`"a" and "b"` keeps its quotes — the interior-quote guard), and unbalanced quotes are content.
- **A naming pass runs on a thread with no tokio runtime → no naming.** `Handle::try_current()` is checked before the `in_flight` claim, so the hook declines rather than panicking; `route_event` runs on the Worker-inbound pump in practice, so this is a guard, not a path.
- **A closed session can still be named if the write lands first, and never emits to a dead UI.** The task holds its own `Arc<Db>` and `Option<Arc<dyn EventSink>>`; a title computed after the row is deleted loses the predicate and writes nothing, and an unset sink (no `set_sink` yet) still persists the title while skipping the emit — a name deserves storing even when nobody can be told about it.
